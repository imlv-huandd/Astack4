# ライセンスファイル v2

関連: [#6717](https://developer.astack.jp/redmine/issues/6717)、[製品ライセンス仕様](../specs/licensing.md)、[旧v1契約](license-v1.md)。

## 販売上の区分

基本機能は有効なライセンスに含める。追加オプションは次の5種類とする。

| 識別コード | 表示名・対象 |
| --- | --- |
| `OPENSEARCH` | 全文検索 |
| `AI_SEARCH` | AI検索 |
| `ACCESS_LOG_AGGREGATION` | アクセス履歴 |
| `CONVERTER_PLUGIN` | Astack Converter Plugin。初期登録の `astack-converter-osdc` エンジンによる実変換 |
| `DOCUMENT_PORTAL_KIT` | ドキュメントポータルキット。外部ツールの契約On/Off。製品内の処理は制限しない |

`BUILD_PIPELINE` はv2の販売オプションに含めない。製品はv2を検証後、基本処理のための内部権利として扱う。基本機能だけの契約は空の `features` 配列で発行できる。実装上AI検索は全文検索の権利も必要とする。

エディションの初期登録は `STANDARD`（Standard）、`LITE`（Lite）。発行システムの管理者は新しいエディションと既定の権利・利用枠を登録できる。具体的な販売値は推測せず、初期エディションは既定値の設定後に発行可能とする。製品はエディション名から権利を補完せず、署名された個別の権利・利用枠だけを使う。

## 署名形式

v1の意味を変更して同じ署名形式を使い回さず、新規発行をv2とする。ファイル上限64KiB、UTF-8、重複キー・未知項目・不正UTF-8・不正サロゲート・末尾の追加JSONを拒否する。文字数はUTF-16コード単位で計数する。

envelopeの項目は `version`（整数2）、`keyId`、`payload`、`signature` の4つ。鍵IDはASCII英数字・`_`・`-`の1〜100文字。payloadと署名はパディングなしの正規base64url。

署名はEd25519、署名対象はUTF-8の `ASTACK-LICENSE-V2\n{keyId}\n{payload}`。LF改行を使用し、payload文字列を再整形せずそのまま署名する。v1とv2のversion・署名領域を入れ替えたファイルは拒否する。

payloadは次の10項目だけを持つ。

| 項目 | 条件 |
| --- | --- |
| `licenseId` | 発行側で生成、1〜100文字・空白のみ不可 |
| `product` | `ASTACK4` |
| `edition` | `[A-Z][A-Z0-9_]{0,31}`。発行時に有効なエディションを選択 |
| `issuedTo` | 契約者名、1〜300文字・空白のみ不可 |
| `issuedAt` | 発行側の現在時刻、UTC秒精度 `YYYY-MM-DDTHH:mm:ssZ` |
| `notBefore` | 同形式、開始時刻を含む |
| `expiresAt` | 同形式またはnull。終了時刻を含まず、issuedAt/notBeforeより後 |
| `installationId` | 小文字の標準UUID表記。ワイルドカード不可 |
| `features` | 上記5コードの配列。空可、未知・重複不可 |
| `limits` | `maxProjects`・`maxLibraries`・`maxDocuments` の3項目だけ |

各上限は0〜9223372036854775807の整数またはnull。nullは無制限、0は枠なし。ユーザー数は利用枠に含めない。ブラウザとの通信は上限を10進文字列として扱い、署名JSONでは整数として生成する。

## 発行マスターと既存契約

オプション・エディションのコードは登録後に変更しない。表示名・説明・有効状態・表示順は管理者が変更できる。物理削除ではなく無効化し、新規発行対象から外す。版番号で競合を検出し、別の管理者の変更を上書きしない。

オプションを追加しただけでは製品の権利チェックは増えない。未知コードはマスターへ保存できるが、製品が対応するまでは発行不可。既知5オプションは発行でき、外部ツール向けのドキュメントポータルキットは契約情報として記録する。

発行時にエディションの既定値を読み込み、必要に応じて個別調整して確認する。発行確定時には現在の有効状態と版を再検証する。発行済みファイル・権利・上限・当時の表示名は保存し、マスター変更や無効化で書き換えない。再ダウンロードは当初の署名済みバイト列を返す。

## v1の継続検証

旧v1ファイルは旧署名領域と旧limits項目を使って検証する。旧 `maxUsers` を新 `maxProjects` へ読み替えない。旧v1のプロジェクト上限は無制限となり、ライブラリ・文書上限は維持する。ユーザー枠は現仕様では適用しない。旧 `BUILD_PIPELINE` の有無による基本権利はv1として維持する。

発行側に保存済みのv1ファイルはそのまま再ダウンロードできる。履歴では旧ユーザー枠をプロジェクト枠として表示しない。v2対応前の製品はv2を受理できないため、製品を対応版へ更新してからv2発行物を登録する。
