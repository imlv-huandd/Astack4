# 検索・公開閲覧・テンプレート

確認基準は [索引](../README.md) を参照。

Reactの管理画面と検索画面は、ブラウザーの優先言語から日本語・英語・ベトナム語を自動判定する。検索語・文書本文・タグ等は翻訳しない。公開テンプレート本体は対象外。詳細は [多言語対応](localization.md) を参照する。

## 標準テンプレート

Astack4の標準バンドルに次のテンプレートを含め、初回起動時に登録する。

| 項目 | 値 |
| --- | --- |
| テンプレートID | `Astack_Default_Template` |
| テンプレート名 | Astack Default Template |
| バージョン | `1.0.0` |
| Astack Ver | `4.0.0` |

公開HTMLのルート表示名（`library.sourceRootName`）はライブラリタイトルを使用し、未設定・空欄・空白のみの場合はライブラリ名を使用する。元文書パスが `./` の場合を含め、保存先のフォルダ名には依存しない。ツリー・パンくず・ルート見出しで共通の表示名を使い、配下のフォルダ名、実際のパス、リンク先は変更しない。既存の公開HTMLはテンプレートビルドで再生成した時点から反映される。

ソースは `templates/Astack_Default_Template/` に配置し、JAR内の `builtin-templates/` にHTML・アセットを同梱する。外部テンプレートディレクトリがない配布環境では、同梱ファイルをデータディレクトリへ展開して登録する。Astack Verは既存の登録処理で `4.0.0` を設定する。

`templates.update` に `templates/update.html`（`mode: html`、`escape: html`）を指定し、ビルド時に公開ルートへ変更一覧を生成する。更新マーク対象の新規追加・更新ファイルを分け、対象期間、件数、表示名、元文書パス、更新日時、容量、閲覧リンク、許可された原本ダウンロードを表示する。対象0件の場合はそれぞれの区分に対象なしを表示する。フォルダ一覧の上部と文書画面の操作欄に変更一覧へのリンクを置く。フォルダと文書のリンクは共通の `update.href` を利用し、階層形式・フラット形式ともに公開ルートの変更一覧へ移動する。変更一覧からは `index.html` へ戻る。CSSは `assets/update.css` をテンプレート資産として公開する。変更一覧追加後もテンプレートバージョンは `1.0.0` とする。

フォルダ一覧の左ペインは、PC幅（761px以上）では境界のドラッグまたは境界にフォーカスして左右キー（16px単位）・Home・Endで幅を変更できる。幅は220～640pxの範囲で、本文に320px以上を残す。選択した幅は同じ公開ルート内のセッションで保持し、画面幅の縮小時は上限へ収める。保存幅はhead内で初回描画前に適用し、操作用スクリプトの読み込みを待つ間も保存幅で表示する。初回描画時の上限はCSSでも制御し、フォルダ移動時に既定幅から保存幅へ切り替わらないようにする。760px以下では従来の開閉メニューを使用する。

旧ID `Astack4_PdfViewer` で登録済みのテンプレートとライブラリの参照は自動変更しない。既存環境では新IDを追加登録し、必要に応じてライブラリの使用テンプレートを変更する。

## 検索

検索画面は既存Reactアプリの `/search` と `/search/:libraryId`。検索APIは認証必須の管理APIとは分離される。ただし転送セキュリティ有効時のWindows認証・ACL検査は適用されるため、常に匿名で全件取得できるという意味ではない。

| API | 用途 |
| --- | --- |
| `GET /api/search` | ライブラリ横断検索 |
| `GET /api/search/{libraryId}` | ライブラリ内検索 |
| `GET /api/search/{libraryId}/count` | 検索件数 |

検索結果取得APIは `q`、`size`（既定10、最大100）、`currentPage`（既定1）、`sortType`（既定score.desc）、`searchType`（既定searchBodyAndFilename）、`searchCondition`（既定AND）、`searchMode`（既定keyword）、`fuzzy`（既定false）、`pathFolder`、`debug` を使う。タグ単独・詳細条件のみ・除外語のみの検索を許可し、検索条件がすべて空の要求は拒否する。件数・ページは1以上、取得範囲は先頭10000件以内、ソートはscore/filename/dateのasc/desc、検索種別はsearchFileName/searchBody/searchBodyAndFilename、条件はAND/OR。管理一覧の0始まりページングと混同しない。範囲・タグ・詳細条件は [検索条件の拡充](search-expansion.md) を参照。

### 検索画面の外観（#6771）

`Astack_Default_Template` と同じ濃紺の文字、青いアクセント、淡い背景、濃紺（`#101e33`）のヘッダーと薄い枠線のパネルを使用する。検索結果は1つの白い一覧枠の中を行区切りとし、検索語の強調・取得元ラベル・文書情報・ページ送りを維持する。検索画面専用のCSS変数とクラスに範囲を限定し、管理画面の配色は変更しない。

検索方式・条件・範囲切替・URLパラメータ・検索API・文書リンク・認証とACLは変更しない。スマートフォンでも条件・文書名・ページ送りへアクセスでき、長い文書名は折り返す。ヘッダーは既存のAstackアイコンとライブラリ名（横断検索は「全ライブラリ横断検索」）を示す。英語のブランド補足・見出しラベル・フッターは表示せず、フォルダツリーや管理画面への新たな導線は追加しない。

### 検索結果のスコア（#6773）

各文書の情報欄に検索APIの `SearchHit.score` を「スコア」として表示する。検索候補の順位を基に計算した関連度の目安であり、百分率へ変換しない。検索方法・ライブラリが異なる値の単純比較には向かないことを説明ボタンで補足する。検索順位やAPIの計算処理は変更しない。

有効数字6桁を目安に表示し、丸め前の値は数値部分のtitle属性へ保持する。0は0として表示し、未取得・null・非有限値は「—」とする。小さい値を固定小数桁で0へ丸めない。キーワード検索・標準検索・横断検索で共通の表示を使用し、狭い画面では文書情報欄を折り返す。

### ライブラリごとの検索対象とAI依存条件（#6767）

内部検索エンジンの検索対象に全文・ファイル名・概要・意味検索を並べる。概要検索は `searchConfig.elasticPreface`、意味検索は `searchConfig.semanticEnabled` で独立してON/OFFを保存する。意味検索は全文検索のON/OFFに依存せず、意味検索だけを選択できる。

- 概要検索はAI処理全体と要約生成がONの場合のみ選択できる。
- 意味検索はAI処理全体とベクトル生成がONの場合のみ選択できる。
- 前提条件を満たさない項目は表示したまま無効化し、理由と「AI処理設定へ」の導線を表示する。
- フォームで前提設定をOFFにすると対応する検索設定もOFFにし、案内を表示する。前提設定を再ONにしても検索利用は自動復帰しない。
- 有効化だけで既存文書を生成済みにしない。AI処理の実行が必要で、未生成の文書は概要検索・意味検索の対象にならない旨を案内する。
- 作成・編集・設定更新APIとインポートで、明示的にONの検索設定と前提条件が矛盾する要求を拒否する。検索時も同じ条件で制御し、古い不整合設定で概要やベクトルを利用しない。

新規フォームでは意味検索はOFF。`semanticEnabled` 未指定の旧設定では、内部検索・本文検索・AI処理・ベクトル生成の従来条件を引き継ぐ。フォームの読み込み時に実効値を表示し、保存時に明示値を記録する。明示的なfalseは常に優先する。DBスキーマ変更・既存索引の再生成は不要。

意味検索OFFでは標準検索・横断検索・件数APIでもクエリ埋め込みを呼び出さず、キーワード検索を利用する。ベクトル生成の設定や生成済みベクトルは変更・削除しない。検索タグ・分類情報のキーワード検索は従来どおり全文検索に含む。

`GET /api/search/options?libraryId=...` は検索画面の選択肢用に `semanticEnabled`（設定上の利用可否）と `semanticReady`（利用可能なライセンスとアクティブなベクトル索引の存在）とライブラリ名 `libraryName` を返す。名前は指定IDの閲覧許可後のみ返し、ID省略時はnullとする。利用可否はID省略時にアクセスできる内部検索ライブラリのいずれかで利用可能ならtrue。指定IDは既存検索と同じWindows認証チャレンジ・ACL検査を行う。接続・モデル・資格情報を返さず、AI APIを呼ばない。モデル接続の実動作や文書ごとの生成完了を保証する値ではない。

検索画面は、意味検索OFFの範囲で標準検索を無効化し、URLにhybridが残っていても実行はkeywordにする。検索範囲を変えたら利用可否を取得し直し、古い範囲の応答を適用しない。設定上ONでも索引未準備等の場合は準備・利用条件の案内を表示し、検索はキーワード検索で継続する。利用可否の取得失敗時も検索本体のサーバー判定を使う。

### 検索方法

- **標準検索（`searchMode=hybrid`）**：全文検索と意味検索の候補を統合する。検索語を含まないが意味の近い文書も対象にする。`searchCondition` のAND/ORはキーワード側の候補に適用し、意味検索の候補へキーワードの包含を要求しない。
- **キーワード検索（`searchMode=keyword`）**：全文検索のみを実行する。意味検索のためのAI呼出しは行わない。AND/OR条件を維持する。全文検索の解析・表記揺れ吸収を利用するため、文字列の完全一致を意味しない。
- ファイル名のみの検索、意味検索無効、`q=*` の全件検索は、標準検索指定でもキーワード検索を使う。AI設定無効・ライセンス対象外・有効なベクトル索引なし・AI障害・結果統合失敗の場合もキーワード検索を継続する。

通常入力は空白で区切った語句ごとのフレーズとして扱い、AND／ORはその語句の間に適用する。`学校教育 受信` のAND検索では「学校教育」と「受信」が同じページに必要で、「学校」と「教育」が離れて存在するだけでは一致しない。`"学校 教育"` のようなASCII二重引用符は明示したフレーズ、`-受信料` や `-"受信 契約"` は文書全体の除外指定とする。あいまい一致をオンにすると通常語句だけを単語分割・誤字補正へ広げ、明示した引用フレーズは維持する。意味検索では通常語句を埋め込み、引用フレーズと除外指定を候補にも適用する。空の引用符・未閉じ・空白なしの引用符連結・100語句超はHTTP 400。詳細は [検索欄の入力方法](search-expansion.md#検索欄の入力方法6788) を参照。

標準検索はライブラリごとにキーワード上位1000文書とベクトル上位1000候補を取得する。候補数はページ番号や表示件数で変更しない。ベクトル候補の表示情報は本文索引から取得し、文書IDで重複を除去してRRF（順位の逆数による統合、定数60）で順位を決める。統合した候補をソートしてからページを切り出す。日付・ファイル名ソートもこの候補集合内で行う。同順位はライブラリIDと文書IDで順序を安定させる。索引・モデル・原本の更新をまたぐスナップショット固定は行わない。

標準検索の `totalHits`・`totalFileCount` は、統合候補のうち公開・ACL再検査を通った文書数。全ライブラリ横断では各ライブラリの結果を統合してからページを切り出す。候補数上限に達した場合やページ送りの10000件上限を超える場合は `config.resultWindowLimited=true` とし、画面で候補を絞っている旨と、検索語の具体化／キーワード検索への切り替えを案内する。意味検索の候補を取得できなかった場合は、従来のキーワード検索の件数とページ送りを使う。

`config.searchMode` は要求したモード、`semanticApplied` は意味検索候補の統合有無、`semanticPartial` は横断検索で一部のライブラリのみ意味検索候補を統合したことを示す。画面は全文検索への切り替え・一部のみの適用を明示する。

検索件数APIも `searchMode`・`fuzzy`・`searchType`・`searchCondition`・`pathFolder` 等を受け付け、同じ条件の検索結果の文書数を `count` に返す。件数APIのモード省略時は `keyword`。標準検索の件数は `searchMode=hybrid` を明示する。候補数上限は `resultWindowLimited` でも返す。検索条件がすべて空の要求・不正モード・不正な入力構文を拒否する。

検索画面はキーワード検索を既定とし、「あいまい一致」「意味検索を含める」は独立したチェックボックスで両方オフから始める。既存URLに明示された指定は尊重する。「すべての語を含む／いずれかの語を含む」を選択でき、モード・あいまい一致・条件は `searchMode`・`fuzzy`・`searchCondition` クエリへ保持する。切り替え時は1ページ目へ戻し、再読込・戻る・検索範囲変更でも条件を引き継ぐ。切り替え前の遅い応答で新しい結果を上書きしない。

OpenSearchの本文・ファイル名に加えAI要約等を検索処理へ連携する。ベクトル索引は本文と分離し、検索時にはアクティブモデルと物理索引の整合を確認する。[AI仕様](ai.md) を参照。文書公開状態・期間・ACLによる絞り込みを両方式へ適用する。ベクトル候補のフォルダ範囲は最新DBの文書IDをk-NN内部のフィルタへ渡して事前制限し、表示情報の取得時にも本文索引のフォルダ条件を検査する。フォルダ指定は配下のパス境界で判定し、`folder` が `folder-other` に一致することを防ぐ。本文を返す直前には最新の公開設定・ACLを再検査し、公開URLは成功済み公開情報から取得する。

### 検索結果の取得元とハイライト（#6766）

各結果の `matchSources` は `keyword` / `semantic` の配列で、候補を実際に取得した方式を順位統合時に保存する。両方に含まれた場合は両方返す。キーワード検索と意味検索のフォールバックは `keyword` のみ、横断検索でも各結果の情報を維持する。全件指定（`*`）は一致語がないため空配列にする。候補取得範囲内の方式を表し、片方のみでも他方式では一致しないという保証ではない。ハイライトの有無から推測せず、順位スコアを一致率として表示しない。

検索結果に「キーワード一致」「意味が近い」のラベルを文字と色で表示し、両方の場合は2つ表示する。共通の `InfoTooltip` でホバー・フォーカス・クリック／タップによる補足を提供する。意味検索には「検索語と関連する内容から見つかりました。検索語そのものが含まれず、ハイライトがない場合もあります。」と説明する。旧APIなど取得元が未提供の場合はラベルを推測表示しない。

タイトルの一致語と本文・要約の一致語を淡い黄色背景＋太字で強調する。本文の前後抜粋（150文字目安）を優先し、なければ要約の一致抜粋を使い、重複を除いて最大2箇所を省略記号付きで表示する。ファイル名の一致はタイトルに表示し、本文抜粋の代替にしない。抜粋がなければ文書要約、未生成なら本文先頭200文字を表示する。意味検索専用の関連箇所抽出・生成要約は行わない。OpenSearchのHTMLエンコードと、属性なしの `em` のみを強調としてReactで描画する既存の安全性を維持する。

複数ライブラリ・詳細条件・タグ活用・検索条件保存・該当ページ移動の追加仕様は [検索拡充仕様](search-expansion.md) を参照。出典付きAI回答は今回の追加対象に含めない。

## 公開とACL

内部公開は `/pub/{libraryName}/...`。URLフィルターのpermitAllだけで閲覧権限を判断せず、公開Serviceのライブラリルート・祖先フォルダ・文書のACL判定を経る。転送セキュリティは単なるボタン表示制御ではない。Windows認証チャレンジと拒否応答を使用する。

ダウンロードの許可、コピー配信とAPI取得、公開原本の削除は [ジョブ・公開](jobs-and-publication.md) の契約に従う。印刷・コピー・ダウンロードのブラウザ上の操作抑止は、配信済みデータの取得やスクリーンショットを完全に防ぐ保証ではない。

## 独立ビューア

公開コンテンツのアクセス履歴は [アクセスログ仕様](access-log.md) を参照。ログ有効時はHTML生成後に共通JSを自動挿入し、テンプレート固有のタグを不要にする。標準PDF・SVGビューアの対応版は1.1.0以降、新しいメタデータと表示失敗通知は1.2.0で、既存の固定版は上書きしない。閲覧操作の拡張とアクセスログを統合した標準パッケージは1.3.0とし、登録済み1.0.0・1.2.0を上書きしない。

ビューアはテンプレートから独立したZIP登録単位。ZIP直下の `viewer.yaml` にID、バージョン、対応形式、提供機能、制限への対応、API/定義版、起動ファイルを記述する。登録済み同一ID・バージョンの上書きはできず、利用中の削除を禁止する。ライブラリは `viewerId` と `viewerVersion` を固定する。

管理APIは `GET/POST /api/viewers`、`GET/DELETE /api/viewers/{id}`、`GET /{id}/download`、`POST /{id}/preview-session`。ライブラリの出力形式は変換プロファイルで決まり、対応するビューアを保存時・ビルド時に検証する。

テンプレートは `converted.viewerHref` から共通呼出しを使う。ビューアは `manifest` クエリで相対URLのマニフェストを受け、`print`・`text`・`download` の0/1を反映する。PDF.jsとSVG文書ビューアを標準提供する。SVGはページの遅延取得・描画の仮想化・キャッシュ・ページ指定印刷を持つ。選択したビューアのJS/CSS等も公開物へ含め、CDNへ依存しない。

内部公開では、構造形式・フラット形式のいずれも `assets/_viewers/` 配下の起動HTML・JS・CSS等を共通アセットとして配信する。ライブラリルートの認証・ACL検査は維持し、同名の元文書に対応するパスは文書ACL・公開設定を優先する。文書マニフェスト・変換ファイル・原本のアクセス判定は各文書に対して行う。

## テンプレートと文書メタ情報

`templateconf.yaml` とThymeleafでHTMLを生成する。XML設定は使用しない。フォルダ画面の `library`、`currentFolder`、`breadcrumbs`、`folders`、`files`、`folderTree`、文書画面の `original`、`converted`、`download`、`security`、`status` 等は `RenderContextAssembler` が組み立てる。権限・公開状態を確認し、提供されない情報を架空の値で埋めない。

### 共通のテンプレート定義と変更一覧

`templates.folder`、`templates.file`、任意の `templates.update`、`search.script0x`、`search.script626`、`search.scriptMetasearch` は、すべて同じ文字列形式または詳細形式を受け付ける。既存の文字列指定は引き続き使用できる。

```yaml
templates:
  folder:
    path: templates/folder_list.html
    mode: html
    escape: html
  file: templates/file_view.html
  update:
    path: templates/updates.csv
    mode: text
    escape: csv
search:
  script0x:
    path: templates/search.html
    mode: html
    escape: html
```

| 設定 | 意味・既定値 |
| --- | --- |
| `path` | テンプレートファイル。詳細形式では必須。既存と同じテンプレート境界・実パス検証を適用する。 |
| `mode` | `html` または `text`。省略時は `.html` / `.htm` が `html`、その他が `text`。 |
| `escape` | `html` / `csv` / `none`。省略時はHTMLモードが `html`、テキストモードの `.csv` が `csv`、その他が `none`。 |

明示指定を優先する。不正な値、未知のオプション、存在しない指定ファイルは設定検証エラーとする。`escape` は `th:text` と `[[...]]` に差し込む値に適用する。`csv` は各値を二重引用符で囲み、内部の二重引用符を二重化する。テンプレートに直接書いたカンマ・改行・ヘッダーは変換しない。CSV値をテンプレート側でさらに引用符で囲まない。`th:utext` / `[(...)]` は明示的な未エスケープ出力であり、信頼できる内容に限定する。HTML属性・JavaScript/CSSの明示的なインライン処理はThymeleafの各文脈の処理を維持する。テキストモードの出力へHTML用アクセスログを挿入しない。

`templates.update` を省略・null・空文字列にした場合、変更一覧の抽出・生成を行わない。指定時は通常の走査・変換・フォルダ生成が終了した後、公開の直前にライブラリDBから期間内の全ファイルを抽出し、公開ルートへテンプレートと同じ末尾ファイル名でUTF-8出力する。例えば `templates/updates.csv` は `updates.csv` となる。フォルダ・文書・検索用の出力先は従来の規則を維持する。

基準日時をビルド開始時に固定し、「新規・更新マークの期間（日）」だけさかのぼった日時を共通の判定開始日時とする。DB登録日時が開始日時より新しければ新規、それ以外で原本更新日時が開始日時より新しければ更新とする。今回の変換・生成対象に限定せず、差分で処理を省略した文書も含める。初回のビルド中に登録した文書も新規に含める。ビルド外の動的描画では最後に公開した日時を基準にする。

変更一覧テンプレートには次の変数を渡す。

| 変数 | 内容 |
| --- | --- |
| `library` | 既存のライブラリ情報。 |
| `files` | 期間内の新規・更新ファイル。`relativePath` 順。既存ファイル一覧と同じ表示名・リンク・公開状態等を持つ。リンクは公開ルートからの相対URL。 |
| `newFiles` / `updatedFiles` | 新規・更新に分けた一覧。 |
| `periodStart` / `periodEnd` | 判定開始日時と基準日時の表示文字列。ビルド中の検出・登録も対象とするため、実際の登録日時が基準日時より後になることがある。 |
| `update.enabled` / `update.filename` / `update.href` | 生成の有無、出力名、現在の生成先からの相対リンク。フォルダ・文書・検索用にも同じ変数を渡す。 |

テキストモードのCSVテンプレート例：

```text
区分,ファイル名,元文書パス
[# th:each="file : ${files}"][[${file.isNew ? '新規' : '更新'}]],[[${file.name}]],[[${file.relativePath}]]
[/]
```

対象が0件でもテンプレートを処理するため、HTML側では「対象なし」の表示、CSV側ではヘッダーのみの出力を記述できる。通常画面への導線は `<a th:if="${update.enabled}" th:href="${update.href}">変更一覧</a>` のようにテンプレート側で追加する。

削除済み・非公開・公開期間外の文書、削除済み・非公開・欠損した祖先配下の文書は除外する。内部公開で権限転送を有効にしている場合は、リクエストごとにフォルダ・文書のACLを反映して一覧を描画し、ディスク上の全件一覧を直接返さない。権限転送なしではビルド済みファイルを返す。外部公開先では従来と同様に公開先側でアクセス制御を行う。

変更一覧は元文書に変更がない差分ビルドでも再評価し、期間外になった項目を除去する。生成失敗時は公開を開始せずビルド失敗とする。出力名が `index.html`・文書出力名・`assets`・隠しファイル名、または元文書/フォルダの生成先と衝突する場合はエラーとする。変更一覧の出力名は公開先ごとの非公開マニフェストに記録し、指定変更・削除時は旧ファイルだけを公開先から除去する。公開失敗時の削除要求は次回へ引き継ぐ。

### Astack_Default_Templateの文書プレビュー

プレビューを最大幅・外側余白なしで画面いっぱいに配置する。黒基調をPDFビューア領域に限定し、外側ヘッダー・検索タグ・文書情報パネルはフォルダ一覧と同じ明るい配色とする。ヘッダーに共有・原本ダウンロード・文書情報のアイコン操作を配置する。元フォルダへのリンクを左向き矢印として文書タイトルの左へ配置し、タグ列の「検索タグ」見出しは表示しない。操作名はaria-labelとtitleで提示し、共有設定と原本の取得可否を継承する。検索タグは実効タグを表示し、1行に収まらなければ「すべて表示」で折り返し表示する。展開領域は高さを制限してスクロール可能とする。

文書情報は初期非表示の右側パネルで、要約全文・タグ・登録メタ情報・基本情報を表示する。基本情報の変換状態を省略する。閉じるボタンとEscで閉じ、起点ボタンへフォーカスを戻す。狭い画面ではビューアに重ねて表示する。PDF以外の独立ビューアも同じ外枠を利用する。

PDF.jsビューアの現行基準版1.0.0は既存のページ指定・倍率・文書内検索・印刷に加え、遅延描画のサムネイル、文書内目次、レイヤー、先頭／末尾移動、回転、縦／横／折り返し／ページ単位スクロール、見開き、手のひら操作、ブラウザが対応する全画面表示、PDFプロパティを提供する。添付保存はダウンロード許可時のみ表示し、PDF内の保存操作も同じ許可に従う。コピー禁止時は文字レイヤー・注釈レイヤー・検索を無効化し、copy/cutを抑止する。印刷は引き続きAstackの許可に従い、通常のブラウザ印刷を抑止して専用の印刷処理を使用する。アクセスログの閲覧・原本保存・印刷イベントは維持する。

本改修完了時点のPDF.js・SVG文書ビューアをともに基準版1.0.0として扱う。今回の初期版整理では旧パッケージ・登録情報を退避して1.0.0を揃える。通常の登録APIは同一ID・同一版の上書きを引き続き拒否し、以後の更新は別版とする。

SVG文書ビューアも領域内を暗色とし、全幅で表示する。アイコン操作、サムネイル、文字情報のあるSVGの全文検索、回転、縦／横／折り返しスクロール、見開き、手のひら、全画面、プロパティを提供する。検索はSVGのtext要素を対象にクライアントで処理し、文字コピー禁止時は無効化する。閲覧・検索・サムネイル・印刷の取得は合わせて最大4件とし、既存の安全化・キャッシュ・仮想化を維持する。SVGに構造化された目次・PDFの添付やレイヤーは提供しない。

ズームボタンで既定の選択肢にない倍率になった場合は、現在倍率を示す一時的な選択肢を1件だけ表示する。既定倍率やページ幅などへ戻した際は一時的な選択肢を除く。

現行PDF.js・SVG文書ビューアは、ビューア側の印刷対象・ページ範囲指定を省き、全ページをブラウザの印刷画面へ渡す。印刷するページ範囲は印刷画面で指定し、元文書とページ番号を一致させる。準備のキャンセル操作は準備中だけ表示し、印刷禁止の制御を維持する。

PDF印刷は、埋め込みフォントが登録されているビューア文書でcanvasへ描画し、PNG画像として印刷用iframeへ渡す。印刷用iframeにcanvasを作るとフォント登録が引き継がれず日本語が欠けるため、描画先文書を分離しない。

サーバーへの保存・送信を伴う機能は追加しない。フォーム編集・注釈編集／保存・署名・AI生成は提供せず、PDF.js本体の描画部品と閲覧APIを用いた操作UIとする。

### Astack_Default_Templateのフォルダ一覧

Astack_Default_Templateは、DOCUMENTS見出しを省き、フォルダ名・件数・共有アイコンを同じ行に配置する。共有設定が有効な場合のみ共有アイコンを表示し、既存のURLコピー・QR・ショートリンクの処理を使用する。ファイル名は同じタブで閲覧ページを開き、操作欄には別タブ表示、原本ダウンロード、詳細のアイコンを並べる。閲覧ページやダウンロード権限がない場合は対応する操作を無効にする。

フォルダ画面の最大幅制限を解除し、PCの左右余白を16pxに統一する。画面幅760px以下では12px、420px以下では10pxとし、一覧と詳細パネルが利用可能な幅に収まるようにする。

ファイル名の下にタグ（最大3件と残件数）と要約を表示する。要約は改行を含んでも1行固定とし、表示幅を超えた部分はCSSの `text-overflow: ellipsis` による「…」で省略する。文字数による事前切り詰めは行わない。要約の長さによって表の幅や行高を増やさない。タグ・要約がなければその領域は表示しない。

詳細は画面遷移せず右側パネルで開き、狭い画面では一覧の下に表示する。要約全文、全タグ、元の名前、形式、容量、更新日、ライブラリ内の相対パス、取得できる場合のページ数を示す。閉じる操作とEscapeキーで起点へフォーカスを戻す。絞り込みで対象文書が非表示になった場合は詳細を閉じる。

フォルダの `files[]` に `summary`、`tags`（手動タグ優先、未指定ならAIタグ）、`pageCount` を追加する。ACL・公開条件・削除状態を検査した表示対象パスのみを100件ずつ検索し、各パスの最新要約を取得する。原本のパス・容量・更新日時・ハッシュの整合性検査は文書画面と同じとし、原本更新前の古い要約やタグを表示しない。検索失敗や該当情報がない場合は追加情報を空にして一覧生成を継続する。テンプレートとバックエンドを更新し、テンプレート更新ビルドまたはフルビルドで既存公開HTMLへ反映する。

詳細パネルの「メタ情報」に、文書メタ管理で登録した項目と複数値を表示する。手動値は現在の実効文書設定から取得し、検索索引がない場合も表示する。手動値がない項目は、原本との整合性を確認できるAIメタ情報で補完する。項目名はグローバル定義をライブラリ固有定義で上書きした表示名を使い、未定義の項目は登録キーを表示する。値のない項目は表示せず、長い項目名・値は詳細パネル内で折り返す。一覧の要約は引き続き1行省略する。`files[].metadata` は表示順に並べた `key`・`label`・`values` の配列。ラベルはフォルダごとに一度だけ取得し、取得失敗時もキー名で表示を継続する。

フォルダ内検索は、現在のフォルダに表示されるファイル名と要約全文を対象に部分一致で絞り込む。大文字小文字を区別せず、検索語中の記号は文字として扱い、空白と改行の違いを吸収する。サブフォルダの内容・文書本文・タグ・メタ情報はこの検索の対象に含めない。従来の日付・容量条件と組み合わせて利用できる。

一致箇所を一覧のファイル名・要約と、詳細のファイル名・要約全文にマークする。一覧の要約は1行を維持し、検索中は最初の一致箇所の周辺から表示する。全文と元のファイル名は保持し、検索解除で通常表示へ戻す。検索文字列をHTMLとして解釈せず、マークと本文をDOMのテキストノードで構築する。

### 式評価とSpring ELへの移行

HTML生成は `SpringTemplateEngine` とSpringStandardDialectによるSpring EL（SpEL）を使用する。`engine.name: thymeleaf` と `apiVersion: 1` は維持する。OGNL依存は削除し、OGNL評価へのフォールバックは行わない。これはCVE-2026-113730の対象ライブラリ自体を除去する対応であり、OGNLの更新PR #17を置き換える。

同梱の9テンプレートは一覧・文書の描画を回帰検証する。未変換文書の `converted.pdfHref` / `converted.viewerHref`、一覧・ツリーの未生成リンク `href`、ダウンロード不可時の `download.originHref` はキーを保持して値を `null` とし、存在しないURLを公開しない。カスタムテンプレートでMapの任意キーを参照するときは、`${optional.get('key')}` のように欠落時も `null` を返す方法を使う。`${optional.key}` はキーが存在しないとSpELでエラーになる。親オブジェクト自体も任意の場合は `${optional != null and optional.get('key') != null}` のように先に確認する。

OGNL固有の式（`@型@静的メソッド(...)`、コレクションの投影・選択など）を含むカスタムテンプレートは、SpELの構文とThymeleafのアクセス制限に合わせて修正する。単純なエンジン名の置換だけで互換と判断しない。導入前に一覧・文書・空フォルダ・未変換/失敗文書・検索有無・公開/ダウンロード制限を確認する。既存公開HTMLは更新だけでは置換されないため、確認済みテンプレートでテンプレート更新ビルドまたはフルビルドを実施して描画結果を確認する。

評価時はThymeleaf標準の型・メソッドアクセス制限を維持し、SpringのApplicationContextやBeanResolverは渡さない。Runtime/Systemへのアクセス、ProcessBuilderの生成、反射経由のクラス読込・クラスローダー取得、Bean参照の拒否を回帰検証する。ただしSpELは任意の未信頼コードを安全に実行するためのサンドボックスではない。テンプレートの登録・更新と保存領域の編集は信頼する管理者に限定する。

NT_Navigator、NT_Finder、NT_Portal、NT_Workbench、NT_Readerはそれぞれフォルダ探索、検索中心、カテゴリ選択、一覧と閲覧、閲覧重視のUXを提供する。実ファイルは `templates/` に置く。各テンプレートへ専用PDF.jsを埋め込む旧設計は、独立ビューアの共通呼出しへ置き換わっている。

テンプレートZIPは `POST /api/templates/upload`。登録DBとディスクの存在を検査し、上書き可否を両方に対して扱う。利用中でもメタ情報編集と明示的上書きは可能。削除は通常利用中を拒否するが `force` 指定を持つ。ビューアの不変バージョン管理と同一仕様にしない。

文書ごとの公開設定は `/api/libraries/{libraryId}/document-meta`。個別取得・削除は `/item?path=...`、実効設定は `/effective`。旧設計の `/{id}` APIではない。

### テンプレートZIPの展開上限

`POST /api/templates/upload` は管理者向けの取込み処理で、次の上限を適用する。サイズの単位はバイトで、上限ちょうどは許可する。

| 設定キー (`astack.template.` 配下) | 既定値 | 対象 |
| --- | --- | --- |
| `max-size` | 104857600 (100 MiB) | アップロードされた圧縮ZIP。Multipart申告値と一時保存後の実サイズを確認 |
| `max-extract-size` | 524288000 (500 MiB) | ZIP全体からコピーする実展開バイト数の合計 |
| `max-entry-extract-size` | 524288000 (500 MiB) | 単一ファイルからコピーする実展開バイト数 |
| `max-entries` | 10000 | ディレクトリを含む全エントリ数 |

ZIPの申告非圧縮サイズは早期拒否に使い、実ストリームを8 KiB以下のバッファでコピーしながら、エントリとZIP全体の残量を検査する。不明サイズ (`-1`) や過少申告でも実バイトで制限し、`-1` 未満の異常値は拒否する。加算前の残量比較によりカウンタのオーバーフローを防ぐ。境界では超過判定のため最大1バイトを先読みするが、上限を超えるデータはディスクへ書き込まない。Zip Slip、OS依存絶対パス、エントリ数の既存検査も維持する。

上限超過・不正ZIP・展開中のI/O例外は `TemplateValidationException` としてHTTP 400で返す。展開量超過の文言は「展開後のサイズが上限を超えています」。失敗時は一時ZIPと `.staging/template_extract_*` 内の部分ファイルを `finally` で削除し、登録DBや既存テンプレートの置換処理へ進まない。削除自体がOS権限・ディスク障害等で失敗した場合は警告を記録するため、運用では残骸と空き容量を確認する。

運用上は1取込みあたり圧縮ZIP用に100 MiB、展開用に500 MiBまでの一時容量に加えて既存テンプレート分の容量を見込む。並行取込み数に応じて必要容量は増える。これらはディスク全体・全リクエスト共通の容量制限ではない。上限変更時はHTTP multipartの制限、利用可能なディスク容量と並行処理数も併せて確認する。

## QRコードアクセス

ライブラリの「閲覧・権限 → 共有・アクセス履歴 → QRコードを有効にする」（`buildConfig.fileQRCodeAccess`）を有効にして再ビルドすると、対応テンプレートの文書閲覧画面に「QRコード」、フォルダ一覧画面に「このフォルダのQRコード」を表示する。Astack_Default_Templateのフォルダ一覧では共有アイコンから開く。Astack_Default_Template、AstackTemplate_ExplorerView、NT_Navigator、NT_Finder、NT_Portal、NT_Workbench、NT_Readerが対応する。

QR画像はボタン押下時にブラウザ内で生成し、文書フォルダに事前生成しない。URLコピーとPNG保存を提供する。外部サービス・CDNへアクセスしない。コピーAPIが利用できない場合は通常のコピーを試し、それも利用できなければURLを選択して手動コピーを案内する。QR容量を超える長いURLは生成失敗を表示し、URLコピーを利用できる。

ショートリンクが無効な場合、QRの対象は現在開いているHTTP/HTTPSの文書閲覧ページまたはフォルダ一覧ページ。実際のホスト・ポート・リバースプロキシのプレフィックスを維持し、クエリ・フラグメント・URLのユーザー情報を除く。原本、変換ファイル、ビューアiframeのURLは使用しない。QR自体に文書データや認証情報を埋め込まず、読み取り後も通常の公開認証・フォルダ／文書ACLが適用される。固定リンク機能は含まないため、公開先・文書パス・配置方式の変更で既存QRが無効になる場合がある。

マニュアル等のフォルダを案内する場合は、該当フォルダを開いて「このフォルダのQRコード」を押し、PNGを保存する。フォルダQRのダイアログは「フォルダのQRコード」「フォルダのURL」と表示し、保存名は `folder-qrcode.png`。通常のビルドで文書一覧を更新すれば、同じフォルダURLのQRから更新後の一覧を開ける。検索・並べ替え等の一時的な表示条件は共有しない。フォルダの配置URL自体を変更した場合はQRを作り直す。

QR・ショートリンク設定、APIパス（システム設定の継承値を含む）・公開方法・サイトURL・ライブラリ名の切替と共通アセットの版をHTML生成の差分判定へ含める。原本未変更のDIFFでもボタンの追加・削除を反映する。アップロード済みカスタムテンプレートには下記の組込みが必要。テンプレート自体の更新後も再ビルドする。

## 必要時発行のショートリンク

「閲覧・権限 → 共有・アクセス履歴 → ショートリンクを有効にする」（`buildConfig.fileShortLink`）をオンにして再ビルドすると、内部Web公開・リモート公開の文書・フォルダ・ルート一覧に「リンクを共有」を表示する。ページ閲覧・ビルドでは文書全件のコードを発行しない。QRだけをオンにした場合は従来の通常URLを使い、ショートリンクだけをオンにした場合はURL表示・コピーを提供する。両方オンなら短縮URLをQRに使う。接続先は「公開・配信 → 外部Webサーバ → APIパス」（`pathConfig.apiPath`）で上書きし、空欄ならシステム設定 `publication.api-path` を継承する。原本ダウンロードと共通で、接続方式の選択項目は設けない。HTTP/HTTPSベースURL（例: `https://astack.example.com/astack`）または同一サイト内のルート相対パス（例: `/astack`、`/`）を指定する。リモートのショートリンクを有効にするには、ライブラリまたはシステム側のAPIパスと、リモート公開先のHTTP/HTTPSサイトURL（`pathConfig.siteURL`）が必要。APIパスには `/pub/{libraryName}/_api` や `/s` を含めず、Astackが付与する。リバプロ経由なら中継先の公開URLを指定し、Astackへの中継はWebサーバー側で設定する。直接接続・リバプロ経由を自動判定・切替しない。

共通APIパスは不足時だけ空欄で登録する。空欄・無効時は共通値を使用せず、ライブラリ指定は引き続き優先する。ビルド開始時に実効APIパスを固定して文書ごとの設定DB参照を避け、途中の設定変更を混在させない。APIパス変更は差分ビルドでもHTMLを再生成する。

ボタン押下時にAstackの `POST /pub/{libraryKey}/_api/short-links` へ `{"kind":"FILE","targetId":123}`（フォルダは `FOLDER`）を送る。`Content-Type: application/json` と `X-Astack-Share: 1` が必須。APIパス設定時はその配下のAPIへ、未設定の内部公開は従来の相対URLへ資格情報付きfetchでアクセスする。別オリジン接続の場合にだけCORSの検査が働く。発行APIだけに、最後に公開成功したリモートサイトのオリジン（スキーム・ホスト・実効ポートが一致）をCORSで許可し、認証を行わない事前要求と実際のPOSTを分ける。ワイルドカードや無関係なオリジンは許可しない。通常のルート認証・ACL・対象の公開状態を検査し、内部公開ではHTMLの実在も確認して、12文字の暗号学的乱数コードを返す。同一対象の同時発行はDBの一意制約で1件にする。任意の転送URLは受け付けない。

クライアントは発行APIのホスト・ポート・公開プレフィックスからAstack側の `/s/{code}` を構成する。`GET` / `HEAD /s/{code}` は現在の認証・ACL・公開期間・除外設定・対象の同一性（内部公開はHTMLの存在も）を再検査し、通常の閲覧ページへ302転送する。応答は `Cache-Control: private, no-store`。不明・失効・停止中のコードは404、認証が必要なら401、権限や公開条件を満たさなければ403。リモート公開では、最後に公開成功したサイトURLと対象の公開ディレクトリから転送先を構成する。リクエストから任意の転送URLを受け付けない。

Viteの開発用Webサーバ（3000番）でも `/s/` で始まる短縮URLをAstackへ転送する。`/settings` や `/search` を転送対象に含めず、302・Location・認証チャレンジ・拒否応答・キャッシュ制御を維持する。

URL保存・ビルド・発行・転送で、APIパス／リモート公開先のDNS解決・HTTP実在確認・疎通テストは行わない。リモート公開はローカルHTMLの残存を要件にしない。利用者がブラウザからAstackへの到達性、HTTPSと混在コンテンツ制約、ブラウザの認証・資格情報送信の可否、公開先の配信状態を管理する。到達性は保証せず、発行済み短縮URLのクリック後の接続エラーも利用者側の責任とする。

発行APIに失敗した場合は通常の公開URLを明示してコピー・QR生成を利用できる。API応答を待っている間はコピーを無効にし、閉じた画面へ遅延応答を適用しない。初回だけでなく共有操作ごとにサーバーで確認し、停止済みコードを画面のキャッシュから返さない。

| 変更パターン | 発行済みリンクの扱い |
| --- | --- |
| 同じ文書の内容更新、フォルダ内の増減、前回公開版の維持 | 同じコードを継続 |
| STRUCTURE / FLAT、テンプレートやハッシュ名の変更 | 公開成功後に転送先を更新。コードは継続 |
| 内部／リモートの切替、リモートサイトURLの変更 | 公開成功後に転送先・許可オリジンを更新。コードは継続 |
| 文書・フォルダ・祖先フォルダの削除、DBからの消失、クロール対象からの除外 | 公開成功後に転送情報を削除して失効。アクセス時も削除状態を再検査 |
| 移動・改名、同じIDでも作成日時が変わった対象、原本接続ID・原本パスの変更 | 別の対象として扱い旧コードを失効。新しい共有時に発行 |
| 削除を検出・確定した後に同じ場所へ再作成 | 新しいコードを発行。古いコードは復活させない |
| 文書メタ設定の非公開・公開期間外、ACL変更 | 即時に利用を制限。情報は保持し、条件を満たせば同じコードで再開 |
| ショートリンク設定オフ | 即時停止。再有効化すると同じ対象のコードを再開 |
| ライブラリのゴミ箱移動・復元 | ゴミ箱中は停止。復元後は同じコードで再開 |
| ライブラリ・プロジェクトの完全削除 | 削除トランザクションの成功後に転送情報を削除 |
| ビルド失敗・キャンセル | 転送情報の整理・更新を確定しない。現在の権限や削除状態によっては閲覧を拒否 |

原本接続・パスと出力方式、内部／リモート公開区分とサイトURLについて、最後に公開成功した設定をライブラリ単位で保持する。原本設定を変更して未公開の状態では発行・転送を拒否し、変更途中の原本にリンクを誤接続しない。削除・再作成がスキャン間に完了して同じパス・同じDB識別情報のままの場合は、通常の内容更新と区別できない。

保存先はメインDBの `short_link`。コードと有効対象の結合キーを索引で検索する。削除時には対象・転送先・結合キーを消し、コードだけを再利用防止用に予約する。`short_link_publication` はライブラリごとの公開成功設定を保持する。追加列 `internal_web`、`site_url` に公開区分と転送先を保存し、旧レコードは内部公開として移行する。文書全件を登録しない。公開成功後の照合は発行済みリンクだけを100件ずつキーセットで処理する。共有・転送時の検査も全ファイル一覧を走査しない。全件再ビルドでも通常は識別子を維持し、ビルドDBを作り直した場合は安全側で旧コードを失効させる。固定ドメインそのものの継続や、移動先の自動追跡は保証しない。

## テンプレート開発ルール：公開アセットの予約領域

| 公開先 | 管理者・用途 |
| --- | --- |
| `assets/_theme/` | テンプレートの `resources.dir` 以下を配布する領域 |
| `assets/_viewers/` | Astackが配布する独立ビューア |
| **`assets/_astack/`** | **Astack本体専用の予約領域**。テンプレートから作成・上書き・削除しない |

テンプレートはQR生成ライブラリを個別に同梱せず、Astackが提供するURLを参照する。Astack本体はQRまたはショートリンク設定が有効な場合に `assets/_astack/qr/` に `qrcodegen.js`、`document-qr.js`、`document-qr.css` とライセンス・配布情報をコピーする。テーマリソースの有無には依存しない。配布失敗を正常扱いにしない。内部公開では、ライブラリルートの通常の認証に加え、共有UI有効時の配布対象ファイルだけを共通アセットとして扱い、同名の元文書がある場合はその文書ACLを優先する。

無効化後の差分公開先に古い共通JSが残る場合があるが、再生成HTMLでは参照・ボタンを除く。内部公開ではQR・ショートリンクの両方が無効なときの共通アセット配信を拒否する。外部静的配信先の古い共通アセットには文書URL・文書データを保存していない。

文書・フォルダテンプレートには次の `qr` モデルを渡す。相対URLはAstackがSTRUCTURE／FLATと配置階層から計算するため、`../` の個数や公開ホスト名をテンプレートで固定しない。共通アセットのURLには版を示すクエリを付与し、更新後のブラウザキャッシュを切り替える。

| 変数 | 内容 |
| --- | --- |
| `qr.enabled` | QRまたはショートリンクの共有UIが有効か。両方無効時もfalseを渡す |
| `qr.qrEnabled` | QRの表示・PNG保存が有効か |
| `qr.shortLinkEnabled` | 内部・リモート公開のショートリンクが有効か |
| `qr.shortLinkEndpoint` | 共通APIパスから構成した発行URL。APIパス未設定の内部公開は従来の相対URL |
| `qr.targetKind` / `qr.targetId` | `FILE` または `FOLDER` とビルドDBの対象ID |
| `qr.generatorHref` | QR生成ライブラリへの相対URL。有効時のみ提供 |
| `qr.scriptHref` | 共通UI JavaScriptへの相対URL。有効時のみ提供 |
| `qr.styleHref` | 共通UI CSSへの相対URL。有効時のみ提供 |

```html
<!-- head内：依存する順序でdeferスクリプトを読み込む -->
<th:block th:if="${qr != null and qr.enabled}">
  <link rel="stylesheet" th:href="${qr.styleHref}">
  <script defer th:src="${qr.generatorHref}"></script>
  <script defer th:src="${qr.scriptHref}"></script>
</th:block>
<!-- 文書操作領域 -->
<button type="button" class="astack-qr-trigger"
        th:if="${qr != null and qr.enabled}" data-astack-qr
        th:attr="data-astack-share-endpoint=${qr.shortLinkEndpoint},data-astack-share-kind=${qr.targetKind},data-astack-share-id=${qr.targetId},data-astack-show-qr=${qr.qrEnabled}"
        th:text="${qr.shortLinkEnabled ? 'リンクを共有' : 'この文書のQRコード'}">リンクを共有</button>
<!-- フォルダ一覧の操作領域 -->
<button type="button" class="astack-qr-trigger"
        th:if="${qr != null and qr.enabled}" data-astack-qr
        data-astack-qr-kind="folder"
        th:attr="data-astack-share-endpoint=${qr.shortLinkEndpoint},data-astack-share-kind=${qr.targetKind},data-astack-share-id=${qr.targetId},data-astack-show-qr=${qr.qrEnabled}"
        th:text="${qr.shortLinkEnabled ? 'リンクを共有' : 'このフォルダのQRコード'}">リンクを共有</button>
```

共通UIは `.astack-qr-*` と `data-astack-qr` を使用する。これらと `window.AstackDocumentQr` は予約名とし、独自スクリプトから上書きしない。静的な文書ページで上記のフックを使えばイベント登録・ダイアログ生成を共通JSが担当する。動的に追加したボタンでは `window.AstackDocumentQr.open(button)` を呼び出せる。ダイアログはEscapeで閉じ、起点ボタンへフォーカスを戻す。

同梱ライブラリはProject Nayuki QR-Code-generator v1.8.0（MIT）。取得元・ハッシュ・再生成方法は [配布情報](../../backend/src/main/resources/publication-assets/qr/README.md) を参照する。共通アセット更新時は `AstackPublicationAssets.QR_VERSION` も更新する。

### テンプレート設定パスの境界（#6682）

`templateconf.yaml` の探索先・設定が置かれたサブディレクトリ、`templates.folder/file`、`search.script0x/script626/scriptMetasearch`、`resources.dir` はテンプレートルート内で解決する。設定サブディレクトリがある場合は、そのディレクトリを参照元の境界とする。正規化した `Path` の要素比較と実パス確認を共通処理で行い、絶対パス、境界外への `..`、Windowsドライブ指定（`C:relative` を含む）、UNC、コロン付きパスを拒否する。バックスラッシュはOSによらず区切り文字として扱う。

設定ファイル、設定サブディレクトリ、テンプレート、資産ディレクトリの子要素を含むシンボリックリンクは、リンク先が内部の場合も拒否する。資産はコピー開始前に全子要素を検証し、読込・コピー直前にも再検査する。Thymeleaf の `th:insert` / `th:replace` などによる動的参照にも同じ境界を適用する。`output.filename` は区切り文字・コロンを含まない単一ファイル名に限定し、`.` と `..` を拒否する。

取り込みと生成は共通の検証を用いる。不正パスまたは資産コピー失敗を警告だけで続行せず失敗として伝播し、不正設定は通常ビルド・テンプレート更新とも事前検査で止めて既存公開版を維持する。正常な内部相対パス、`./`、内部に収まる正規化可能なパス、未存在の任意資産ディレクトリは従来どおり扱う。同梱テンプレートの設定互換性は回帰テストで確認する。

拒否された既存テンプレートは、参照先を設定ファイルのディレクトリ内へ実ファイルとして同梱し、設定値を相対パスへ変更して再登録する。リンクのまま再登録しない。テンプレート保存領域は管理者だけが更新できる運用を維持する（検証と読込の間の悪意ある同時ファイル置換をOSレベルで排他する仕組みは本修正の対象外）。

## 公開SVGの保護（#6720）

変換済みSVG（変換省略したSVGを含む）は公開コピー時に静的なSVG描画要素へ制限する。script、イベント属性、foreignObject、SMIL、外部URL参照、SVGを含むdata URL、外部CSS・難読化CSSを除去し、DOCTYPEを拒否する。内部のパス・テキスト・グラデーション、同一SVG内参照、埋込みPNG/JPEG/GIF/WebPと通常のクラスCSSは保持する。SVG内リンク・アニメーション・外部画像等はプレビューでは提供しない。元文書は書き換えず、原本のダウンロード経路を利用する。

内部公開APIは既存のSVGも配信時に無害化し、SVG応答に `Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:` と `X-Content-Type-Options: nosniff` を付与する。許可トークンのないsandboxによってスクリプトと同一オリジン権限を付与しない。[CSP sandbox仕様](https://www.w3.org/TR/CSP3/#directive-sandbox)を参照。ビューアのfetchとDOMへの描画・印刷は既存のDOMPurifyと併用する。

外部Webサーバーへの公開は、修正版で全件再生成・再公開し、旧SVGを残さない。管理画面とは別オリジンを使用する。WebサーバーでもSVGの応答へ上記のCSPとnosniffを設定し、原本配下はattachmentで配信する。HTTPヘッダーをHTMLのmetaやSVG内部へ記載して代用しない。外部サーバーの設定は転送データだけでは保証できないため、配信URLで確認する。今回の開発環境では外部IISの配信検証を行わない。
## 検索時のライブラリDB接続（#6731）

検索本体は管理DBの読取トランザクションを維持する。文書の検索対象フィルター生成・許可判定・表示直前の再判定では、`SearchDocumentAccessService` 内のライブラリDB読取ブロックだけ外側トランザクションを一時中断（`NOT_SUPPORTED`）し、対象ライブラリのフォルダ・文書・祖先ACLを参照した後に管理DBトランザクションへ戻す。`LibraryDatabaseContext` の切替だけでは既に束縛されたJDBC接続は変わらないため、この境界を保つ。

管理DBのメタデータ参照は外側の既存トランザクションで行い、接続を追加取得しない。検索本体のセッションを閉じないことで、公開可否判定に必要な変換プロファイル・エンジンの遅延読込も維持する。例外時も元のトランザクションとライブラリコンテキストを復元する。DBスキーマ・保存データ・API形式の変更や再インデックスは不要。

## Side by Sideテンプレート（#6777）

`Astack_SideBySide_Template` は `Astack_Default_Template` の配色・フォルダツリー・文書画面を基にした左右ペイン形式。左側には全フォルダのツリーとカレントフォルダ直下のファイルだけを表示する。他フォルダのファイルを先読みしない。フォルダリンクはそのフォルダの `index.html` へページ遷移し、ファイルリンクは右側の名前付きiframe `document-pane` に既存の文書画面を表示する。文書ヘッダー・印刷・情報パネル等の操作は既存ビューアを利用する。未変換等で閲覧リンクがない項目はリンクを生成しない。公開期間・権限のフィルタは既存のフォルダコンテキストを用いる。

初期ページは任意の `templates.top` で定義する。従来テンプレートでは省略でき、指定がなければ初期ページを生成しない。

```yaml
templates:
  folder: templates/folder_list.html
  file: templates/file_view.html
  top: templates/top.html
  update: templates/update.html
output:
  filename: index.html
  topFilename: top.html
```

`templates.top` は他の定義と同様に文字列または `path/mode/escape` のオブジェクト形式。`output.topFilename` はライブラリ直下に生成する単一ファイル名で、省略時はtopテンプレートの末尾ファイル名を使う。絶対パス・親ディレクトリ・予約出力名・文書出力名・変更一覧との衝突を拒否する。入力フォルダ・文書と出力が衝突する場合も公開前に失敗させる。

トップページには `library`、`buildTime`、`update` を渡す。`buildTime` はビルド開始基準時刻。Side by Sideの `top.html` はライブラリ表示名、ビルド日時、変更一覧へのリンクを表示する。フォルダコンテキストの `top.href` は現在フォルダから初期ページへの相対リンク。初期ページはルートに1つ生成し、通常・テンプレート更新の公開対象とする。出力名変更・無効化時は公開マニフェストで以前の生成ページだけを削除し、失敗した公開の再試行でも引き継ぐ。

内部配信はライブラリのアクセス判定を通し、設定された初期ページだけを配信する。任意のルートHTMLを公開する扱いにはしない。狭幅ではメニューボタンから左側を開閉できる。単一フォルダ内のファイル件数が非常に多い場合のページ分割・遅延描画は今回の対象外。

### 左右ペインの幅と初期ページ配置（#6779）

PC幅（901px以上）では境界を左右にドラッグして左ペイン幅を変更できる。左ペインの初期幅は292px、最小220px、最大640pxかつ右ペインに320px以上を残す。iframe上でもドラッグを継続し、操作終了・キャンセル・画面外へのフォーカス移動時には捕捉を解除する。境界へのキーボードフォーカス時は左右矢印で16pxずつ、Home/Endで最小/最大へ変更する。同じライブラリのフォルダ移動中はタブのsessionStorageで幅を保持し、画面幅変更時は利用可能な幅へ収める。狭幅では従来のメニュー開閉を使い、境界は表示しない。

`top.html`の内容は右ペインの縦横中央に配置する。狭い画面では長いライブラリ名を折り返し、内容が画面より高い場合はスクロール可能にする。

Side by Sideの変更一覧では、ライブラリ全体を右ペイン内に入れ子で開かないよう、ヘッダー・フッターの「ライブラリへ戻る」リンクを置かず、ロゴ・パンくずもテキストとして表示する。ライブラリ内の移動は外側に常設されたツリーと「トップ」を使い、変更一覧から文書を開くリンクは右ペイン内で維持する。既定テンプレートの戻るリンクは維持する。


## 共通ビューア起動処理（#6794）

起動ページのHTML/JS/CSSはAstack本体の共通資産で管理し、ビルド時に公開先の `assets/_astack/launcher/` へ静的ファイルとしてコピーする。テンプレートやビューアごとに変換制御を実装しない。テンプレートの `converted.viewerHref` は共通起動ページを参照する。実際の成果物の存在とビューアを起動できる能力を分け、未変換でも変換可能な文書には起動URLを提供する。

PRECONVERTは公開先の静的マニフェストを指定して登録済みビューアを起動する。変換APIの疎通確認・自動フォールバックはしない。BACKGROUND/ON_DEMANDは公開時に生成した設定に従い、同一オリジンのAPIへ変換要求を送り、状態をポーリングして完了後に既存ビューアを起動する。待機・処理中・失敗・旧版の表示は起動ページ内で更新し、文書HTMLの再公開を必要としない。ページ・検索語の指定はビューアへ引き継ぐ。

状態取得・変換要求・成果物配信は `/pub/{libraryKey}/_api/files/{fileId}/preview` 配下に置き、公開APIの接続元制限と公開条件・ライブラリ/祖先/文書の認証・ACLを維持する。原本の任意パスをクライアントから受け付けない。

## 公開ページへの検索表示（#6806）

ライブラリ設定の「検索 → 公開ページの検索 → 公開ページに検索を表示する」で検索導線を切り替える（`searchConfig.showOnPublishedPages`）。内部検索・外部検索のどちらにも適用し、OFFでも管理画面の検索は維持する。検索なし・独立配信では常に非表示とする。未指定は従来の表示を継承する。反映はTEMPLATEで可能とし、公開・閲覧権限や検索APIの利用権限は変更しない。

AIが有効な場合は検索方式や公開ページへの表示に関わらず本文抽出・内部索引を準備する。詳しくは [AI仕様](ai.md) を参照。


## 文書サムネイルの表示（#6838）

`converterConfig.showThumbnail`（画面名「サムネイルを表示する」、既定true）は生成有効時に適用する。フォルダ・変更一覧の `files[].thumbnailHref`、文書画面の `converted.thumbnailHref` を提供し、無効・未対応時はnull。標準テンプレートとNT系フォルダ一覧は生成画像を表示し、ファイル詳細の文書情報には画像を表示しない。独自テンプレートはこれらのキーを利用できる。

検索結果の `source.thumbnailUrl` は検索索引へ保存せず、公開済み文書URLの解決・認可後に付加する。画像完成による再インデックスは不要。生成予定のURLを含むため、URLがあっても画像の存在を保証しない。画像は遅延読み込みし、読み込み完了までは従来アイコンを表示する。未生成・取得失敗時にもアイコンを維持し、一覧・検索・文書閲覧を待たせない。画像の完成は次回の画面表示・再読み込み・検索時に反映する。

表示設定の変更後はHTMLの再生成・再公開が必要。生成設定・変換方式の変更後は全件再ビルドする。

## 文書ビューアのピンチ操作（#6844）

PDF.js・SVG文書ビューア1.0.0は、文書領域内の2本指ピンチとCtrl付きwheelで通知されるトラックパッドのピンチで拡大・縮小する。指の中心付近の文書位置を保ち、倍率表示も同期する。倍率はPDFが25〜400%、SVGが10〜600%。1本指のスクロール、倍率ボタン、文字選択、手のひらのマウス操作は維持する。標準・左右分割テンプレートのファイル詳細にサムネイル画像を表示しない。一覧とビューア内のページサムネイルは維持する。リリース前のため同梱版は1.0.0に統一する。開発環境では登録済みの標準パッケージも同じ内容へ揃え、対象ライブラリを1.0.0で再公開する。独自に登録したパッケージは変更しない。
