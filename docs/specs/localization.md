# 管理画面・検索画面の多言語対応（#6810）

## 対象と言語の判定

Reactで提供するAstack管理画面（ログイン、各管理一覧・登録編集・確認・補足を含む）と `/search`・`/search/:libraryId` を、日本語 `ja`・英語 `en`・ベトナム語 `vi` で表示する。テンプレート管理画面の操作文言は対象だが、公開テンプレート本体・生成HTML・埋め込む文書ビューア本体は対象外。

初期化時に `navigator.languages` を優先順に調べ、最初に一致した対応言語を使う。リストが空なら `navigator.language` を使う。地域指定は基本言語へまとめる（`en-GB` → `en`、`vi-VN` → `vi`）。すべて未対応、またはブラウザー情報がない場合は日本語。例：`de-DE, vi-VN, en-US` はベトナム語。

今回は自動判別のみで、手動切り替え、localStorageへの言語保存、ユーザー設定・DB項目の追加は行わない。ブラウザーの言語設定を変更したらページを再読み込みする。モジュールで定義するフォーム項目や状態ラベルも同じ初期言語で揃える。管理画面と検索画面は同じ判定を使い、HTMLの `lang` も設定する。

## 実装と配信

`frontend/src/i18n/index.ts` で専用のi18nextインスタンスを作成し、`initReactI18next` と接続する。翻訳辞書は `locales/ja.json`・`en.json`・`vi.json`。3言語を静的importし、同期初期化して最初の描画・モジュール定数の評価に間に合わせる。

辞書はViteのJavaScript成果物へ同梱する。既存のビルド出力先 `backend/src/main/resources/static` とSpring Bootの静的配信を維持し、言語別HTMLや専用API、翻訳サービス、実行環境のNode.jsは不要。辞書の更新時はフロントエンドの再ビルド・配布が必要。稼働後の翻訳に外部通信は行わない。

表示専用の日本語文言を自然言語キーとして `translate('保存')` のように参照する。句読点やピリオドもキーの一部なので、`keySeparator`・`nsSeparator` を無効にする。日本語の修正時はキーと3言語の辞書を同時更新する。未登録キーは元の文言へ、既存キーの翻訳欠落は日本語へフォールバックする。

動的な値は `translate('ライブラリ #{{value0}}', { value0: libraryId })` のように埋め込む。件数・確認文などは文章全体を辞書に持たせ、翻訳側で語順を変更できるようにする。Reactのテキスト・属性として描画し、HTML文字列として挿入しない。

英語の件数・時間単位などは必要に応じて `_one` の単数形を追加する。単数形のある文言は先頭の数値 `value0` をi18nextの `count` に渡し、単数・複数を選ぶ。明示的な数値 `count` も指定できる。日本語・ベトナム語は基本形を使う。

## 翻訳する値・保持する値

- メニュー、ボタン、ラベル、プレースホルダー、通知、確認、フロントエンド入力検証、補足、アクセシビリティ用ラベルを翻訳する。
- 日時・数値表示は判定した言語に対応する `ja-JP`・`en-US`・`vi-VN` を使う。既存の日本時間指定、APIのLocalDateTime表記、日付入力・検索条件の意味は維持する。
- プロジェクト名、ライブラリ名、文書名・本文・要約・タグ、入力途中の値、保存済み設定、生成プロンプト、プロトコルコード・ステータス値、ログ本文は翻訳しない。
- APIエラーは表示時に辞書の既知文言を翻訳する。API応答・HTTP状態・認証処理は変更しない。未知のサーバー診断文・接続先サービスのメッセージは原文を保持する。利用者が登録した説明も一律には翻訳しない。
- 標準設定の説明は既存の `descriptionHelp` による既知文言の対応表を翻訳し、照合用の原文キーを保持する。

## 検証と反映

`frontend` で `npm ci`、`npm test`、`npm run lint`、`npm run build` を実行する。多言語の検証は `tests/i18n.test.cjs` に含める。

- 言語の優先順・地域指定・未対応時のフォールバック
- 3辞書のキー・変数の一致、空文字・未処理文字・静的UI文言の翻訳漏れ
- 各言語の検索・ページ送り・フォーム定義の初回描画
- 入力値・保存する名前や生成要件の保持、埋め込み値のHTMLエスケープ

ブラウザーでは3言語と未対応言語でログイン、管理一覧、モーダル、検索・条件・ページ送り、狭い画面の操作を確認する。Spring Bootで配信するビルド成果物でも確認する。

反映前に稼働中のフロントエンドとバックエンドの構成・ハッシュを記録し、他の反映済み変更を保持する。既存のDB・ライセンス・鍵のバックアップと、変更前の配信物へ戻す手順を用意する。フロントエンドだけを更新する場合も稼働中JARの他のエントリーを保全し、再起動後にヘルス、認証API、検索API、設定・ライセンスの保持と3言語の画面表示を検証する。DBマイグレーションはない。
