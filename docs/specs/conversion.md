# 変換エンジン・プロファイル

確認基準は [索引](../README.md) を参照。

## 設定の責務

| 設定 | 責務 |
| --- | --- |
| コンバーターエンジン | 実行方法・接続先・対応入力形式・対応出力形式・並列起動数上限・ファイル変換タイムアウト |
| 変換プロファイル | 使用エンジン、単一の `outputFormat`、既定パラメータセット、タイムアウトの上書き |
| ライブラリ | 使用プロファイル、`parameterOverrides`、追加パラメータ、ビューアと固定バージョン |

出力形式はプロファイルで確定する。ライブラリで出力形式だけを独立して選ぶ旧設計は使用しない。エンジンの対応形式の範囲で保存し、ライブラリのビューアとの整合を保存時・ビルド時に確認する。

有効パラメータはプロファイル既定へライブラリの上書き・追加を適用したもの。エンジンの別パラメータ一覧を混入させない。必須・読取専用・真偽値・空文字や引数の衝突を検証する。出力形式、実行設定、有効パラメータを差分判定の署名に含め、ビルド開始時の設定を固定する。形式・有効値の変更は再変換対象、同一設定の再保存や同形式のビューア変更だけでは不要な再変換をしない。

画面の見出しは「パラメータ設定」。編集可能欄は白、読取専用は灰色、調整済みの青枠とリセット操作を持つ。

## PDF原本と出力形式の切り替え（#6837）

標準OSDCエンジンの対応入力にはPDFを含め、新規登録時・既存標準エンジンの起動時更新で反映する。出力形式がSVGならPDF原本もOSDCでページ別SVGへ変換し、SVG文書情報を生成して指定ビューアへ渡す。原本と出力が同形式の場合だけ「同形式の原本は変換を省略」の設定を適用する。ビューアだけを変更して出力形式を決めることはしない。

PDF出力からSVG出力への切り替えは、原本の更新有無にかかわらず再変換対象とする。過去に「変換対象外の拡張子」としてスキップされた文書も、現在の入力・出力設定で処理可能なら差分ビルドから再試行する。削除済み・公開除外の文書や、引き続き未対応の形式はこの復旧対象にしない。事前変換・バックグラウンド変換・オンデマンド変換は同じ対応形式判定を使用し、公開後変換は更新設定で再公開して反映する。

PDFの暗号化や権限制限などでエンジンが変換できない場合は、通常の変換失敗として理由を記録する。OSDC V12の付属マニュアル「PDFからの変換」ではPDF→SVG対応と、内容のコピー・抽出が禁止されたPDFなどの制限を定めている。

## 新規登録時の実行パス

コンバーターエンジンの新規登録では、実行パスを空欄で表示する。`GET /api/converter-engines/defaults` の `convertUrl` は空文字とする。プレースホルダーは架空のWindowsコマンド `C:\Tools\SampleConverter.exe -in {input} -out {output}` を例示し、入力値として保存しない。実行パスは必須のままとし、利用者が実際の設置先・引数を入力する。編集時は保存済みの値を表示する。起動時の標準エンジン初期化に使うOS別既定値と、既存の登録済みコマンドは変更しない。

## 並列起動数上限

エンジンの `maxConcurrentJobs` は1〜64の整数、既定値1。作成時の省略は1、更新時の省略・nullは現在値を保持する。編集画面、一覧、詳細API、JSONエクスポートに含める。既存エンジンのDB列にも既定値1を適用する。

同じエンジンIDを使う全ライブラリで実行枠を共有し、全体の `build.converter.concurrency`（既定4）との両方を満たす範囲で起動する。

全体上限はシステム設定の「詳細設定一覧 → 全体の変換ワーカー数」で管理し、1〜64の整数を保存する。保存後、次回の処理確認（通常1秒間隔）でワーカープールのサイズと起動枠へ反映し、再起動は不要。減少時も実行中の変換は完了まで継続する。初回のみ起動設定の値をDBへ引き継ぎ、以後は有効なDB設定を優先する。設定の無効・削除・既存不正値は起動設定へ戻し、DB取得失敗時は新規起動を待機する。

枠を起動前に予約し、予約中も上限へ算入する。上限待ちは `QUEUED` のまま、開始時刻・試行回数を変更しない。同一ライブラリでは優先度・作成日時順の候補を確認し、枠の埋まったエンジンを除外して別エンジンや別ライブラリの処理を継続する。空き枠は共通スケジューラーの1秒間隔の確認で補充する。

### ライブラリ間の割り当て

事前変換と公開後変換の待機キューを共通スケジューラーで横断し、次の空き1枠ごとに割り当てる。オンデマンドの閲覧要求と、閲覧により優先度を上げたバックグラウンド変換を最優先とする。実行中の変換は中断しない。

ライブラリ設定「変換・ビルド → 通常変換の優先確保数」（`converterConfig.normalConversionTarget`）は1〜64、既定1。事前変換・通常のバックグラウンド変換に対する混雑時の目標数であり、最低保証や上限ではない。オンデマンド変換を選択した場合はこの項目を非表示にする。方式の切り替えでは入力値・保存済み値を保持し、事前・バックグラウンド変換へ戻すと再表示する。保存後の割り当てから反映し、再ビルド・再起動・再変換は不要。本文索引・AI入力の世代判定にも含めず、既存の索引ジョブや処理済み結果を維持する。

通常変換は目標未達のライブラリを優先し、実行数／目標数の充足率が低い順、同率では最後の割り当てが古い順で配分する。ライブラリ内は受付順。全ライブラリが目標を満たす場合の余剰枠は、事前・バックグラウンドを同じ優先度として両キューの受付順に割り当てる。実行不能なエンジンの枠待ちは飛ばし、他の実行可能なタスクへ進む。

競合がなければ1ライブラリでも空き枠をすべて利用できる。後から別ライブラリの待機が生じた場合は、実行中の処理が終わるたびに1枠から配分を見直す。4枠にA・B・Cが各2を希望しても全体上限を超えず、2・1・1などで稼働し、完了に合わせて公平に巡回する。閲覧要求は目標に優先するため通常変換は一時的に目標を下回ってよく、閲覧処理の終了後に未達分へ戻す。ビルド用の固定予約枠や1ワーカー時の待機時間は設けない。全体上限とエンジン上限は全方式に適用する。

起動判定ではビルド開始時のスナップショットではなく最新の上限を参照する。上限引下げ時も実行中の処理は停止せず、実行数が新しい上限を下回るまで新規起動を待つ。成功・失敗・タイムアウト・取消・投入失敗で枠を解放する。実行中の取消はFutureの取消通知だけでは解放せず、処理の終了を待つ。再起動時の未完了ジョブの失敗処理は従来どおり。

枠はアプリケーション内で管理する。現在のビルド実行基盤と同様に、同じDBを共有する複数アプリケーションインスタンスの同時稼働は対象外。並列数は変換結果や差分判定の署名には含めない。

`ddl-auto=update` では列が自動追加される。`validate` の環境では停止・バックアップ後、更新版起動前に管理DBへ次を一度実行する（H2）。

```sql
ALTER TABLE converter_engine ADD COLUMN IF NOT EXISTS max_concurrent_jobs INTEGER DEFAULT 1 NOT NULL;
```

OSDCは初期値1から始め、代表的な実文書を使ってCPU・メモリと変換時間を計測し、2、3と段階的に増やす。同じ実行プログラムを別エンジンIDで登録した場合は枠が別になるため、合計負荷を考慮する。

## ファイル変換タイムアウト

エンジンの `timeoutSeconds` は1〜2147483647の整数（秒）、既定300秒。エンジン作成時の省略・nullは300、更新時の省略・nullは現在値を維持する。プロファイルの `timeoutSeconds` は同じ範囲の整数またはnull。作成・更新の省略・nullはエンジン設定の継承に戻す。プロファイル編集では空欄を「コンバーター設定を継承」と表示し、エンジンの現在値も案内する。小数・文字列・0・負数・整数範囲外をAPIで拒否する。

適用順はプロファイル指定値、エンジン指定値、既定300秒。エンジン管理とプロファイル管理の登録・編集で設定し、詳細・一覧API、エンジンのJSONエクスポートでも保持する。従来の `build.converter.timeout-seconds` による一律指定は使用しない。既存環境は導入時に300秒となり、従来の起動設定で調整していた場合は画面からエンジンへ設定し直す。

各ファイルの外部変換開始直前に管理DBから最新値を取得する。保存後に開始する変換・再試行から再起動不要で反映し、実行中のプロセスの制限時間は変更しない。出力設定はビルド開始時のスナップショットを維持し、タイムアウトのみ最新値を読む。途中でプロファイルの使用エンジンが変わった場合は、ビルドで選択済みのエンジンと一致するプロファイルの値だけを使用する。DB取得失敗・設定不正時は上限なしで実行せず、既存の変換失敗処理へ渡す。タイムアウトは変換結果の署名に含めず、この値の変更だけでは変換済みファイルを再変換しない。ビルド全体の待機上限 `build.worker.conversion-timeout-seconds` とは独立する。

`ddl-auto=update` は追加列を自動作成する。`validate` 環境では停止・バックアップ後、更新版起動前に管理DBへ次を実行する（H2、既存行・再実行を保持）。既存エンジンは300秒、既存プロファイルは継承となる。

```sql
ALTER TABLE converter_engine ADD COLUMN IF NOT EXISTS timeout_seconds INTEGER DEFAULT 300;
ALTER TABLE conversion_profile ADD COLUMN IF NOT EXISTS timeout_seconds INTEGER;
```

## 標準PDFとSVG

標準PDFと標準SVGプロファイルを併存させ、PDFの既定選択を維持する。標準SVGはCLI方式かつSVG対応のエンジンに追加する。同名の既存プロファイルや無効化を保持し、起動のたびに重複・上書きしない。

SVGはページ単位で生成し、総ページ数と寸法をマニフェストへ記録する。標準設定はSVG 1.1、画像埋め込み、自動画像変換、JPEG品質80など計8項目。品質80はAstackの標準指定値。ページ分割・名前は変換基盤が管理し、オフライン用の画像埋め込みは固定する。

| パラメータ | 初期値 | 内容 |
| --- | --- | --- |
| svgver | SVG1.1 | SVG仕様 |
| svgip | 0（読取専用） | 全画像を埋め込む |
| svgic | 0 | 画像形式の自動選択 |
| svgjq | 80 | JPEG品質 |
| docpagenumbercorrection | false | 目次ページ番号補正 |
| xlscontinuepagenumber | false | Excelページ番号連番 |
| pptnotes | false | PowerPointノート |
| extlevel | 2 | エラー中止レベル |

変換入力を作業領域へコピーし、成果物は非公開の保存領域と公開先を分ける。入力スナップショットと公開成功版の対応を保持する。フォルダ完了はDBの条件付き状態更新で取得し、並行通知から重複生成しない。

## 出力形式一致時の省略

原本の拡張子と出力形式が一致し、変換省略が有効なら原本コピーを使用して変換タスクを `SKIPPED` とする。単に成功へ置換しない。コピー済みPDFの検索登録やAI入力は維持し、コピー・索引登録のエラーは失敗処理へ渡す。個別失敗後の公開は [ジョブ・公開](jobs-and-publication.md) を参照。

## 同名ファイル対応と変換キャッシュ（未提供）

Astack4では、拡張子の異なる同名文書を制御する「同名ファイル対応」設定、および利用者がON/OFFできる変換キャッシュ設定は未提供とする（[#6726](https://developer.astack.jp/redmine/issues/6726)）。両者は異なる概念であり、同名ファイル対応を変換キャッシュへ読み替えない。仕様未確定のため選択肢を画面に表示しない。既存の差分検出や変換省略は、それぞれの既定の判定に従う。

`converterConfig.enableConvertCache` はAPI・既存JSON・インポートとの互換性のため読み書きを維持するが、実行処理を変更しない。フォーム内も同じキーで保持し、旧UI名 `enableSameNameFile` からの送信時マッピングを廃止する。既存値を編集・複製・再保存で維持し、一括削除・移行は行わない。旧UIから既に保存された値から同名処理の意図は復元しない。

同名ファイル対応の項目除去は暫定対応であり、今後の機能追加を予定する。#6726は再オープン済みで、同名ファイル処理の仕様確定・実装・検証が完了するまでクローズしない。誤マッピングの解消や項目の非表示だけで機能実装完了とは扱わない。


## 変換タイミングと原本の更新確認（#6794）

ライブラリの `converterConfig.conversionTiming` は `PRECONVERT`（事前変換、既定）、`BACKGROUND`（バックグラウンド変換）、`ON_DEMAND`（オンデマンド変換）。事前変換は従来どおり変換後にHTMLを公開する。後の2方式は走査・HTML生成・公開を先に完了し、公開成功時に固定した設定で閲覧用変換を別途実行する。BACKGROUNDは全件を順次処理し、閲覧要求のある文書を優先する。ON_DEMANDは閲覧時だけ変換タスクを作成する。事前・バックグラウンド変換のFULLは全件を再変換対象へ戻す。オンデマンドはFULLでも未要求文書のタスクを作成せず、既存成果物の有無・原本・設定を閲覧時に確認する。DIFFは必要分、TEMPLATEは原本走査・再変換を行わない。

`converterConfig.updateCheckMode` は次の3択。ビルド時と連携方式の閲覧時に使用する。

| 値 | 画面 | 動作 |
| --- | --- | --- |
| `METADATA`（既定） | 更新日時・サイズで確認 | いずれかが変われば再処理。変更判定のためのハッシュ計算を行わない |
| `CHANGED_HASH` | 変更検知時に内容も確認 | メタ情報変更時に内容ハッシュを比較し、内容同一なら再変換を省略 |
| `ALWAYS_HASH` | 毎回内容を確認 | メタ情報が同一でも全内容を確認。同サイズ・同日時の変更も検出 |

METADATA/CHANGED_HASHでは日時とサイズが維持された内容変更を検出できない。ハッシュを使わなくても、変換・本文抽出時の原本取得は必要。出力欠損と変換設定の署名変更は原本の更新有無と別に再処理対象とする。

公開後の変換ジョブはビルド用コンテキストと独立して永続化し、同一文書の同時要求を集約する。全体・エンジン別の変換枠は事前変換と共有する。取得した原本コピーを固定して変換し、取得前後の整合と公開版を確認してから不変の成果物を確定する。変換途中のファイルを配信しない。公開し直した版・削除した文書を古いジョブが復活させない。再起動時は未完了ジョブを再確認し、同一内容の失敗を無限に再試行しない。

本文抽出と検索索引・AI処理は閲覧用変換から独立させる。[原本本文抽出](source-text-extraction.md)を参照。


## 文書サムネイル（#6838）

`converterConfig.generateThumbnail` は既定false。対応アダプターを持つエンジンでのみ選択できる。初期対応はOSDCのコマンドライン接続で、画像出力拡張子の登録だけを対応能力とみなさない。エンジンAPIは `thumbnailSupported` を返す。

文書変換と同じタイミング・予約枠で先頭ページをPNGに出力し、縦横比を維持して長辺480px以下に正規化する。切り抜かない。画像変換は最大30秒（エンジンの上限が短い場合はその上限）。生成失敗は警告として記録し、文書変換の成功を変更しない。同形式の原本をコピーする場合も画像を生成する。

`thumbnail.png` は変換済み文書と同じ文書用ディレクトリに保存する。事前変換では付随成果物としてキャッシュ・コピー・公開・削除する。原本の隣には書かない。生成有効化は変換署名に含め、既存文書も更新対象にする。表示設定のみの変更は再変換せずHTML再生成で反映する。

オンデマンドでは追加オプション `sequentialThumbnails`（画面名「サムネイルを順次生成する」、既定false）を提供する。生成有効・オンデマンドの場合だけ適用する。公開成功後に画像だけの永続キューを作り、閲覧要求・通常変換より低優先度で全体・エンジンの空き枠を利用する。通常変換の優先確保数には数えず、実行中の処理は中断しない。文書本体の閲覧要求や変換ジョブは作らない。再起動時は試行数を保持して中断分を復旧し、繰り返す中断や生成失敗は自動で無限再試行しない。

原本接続・パス・日時・サイズ・ハッシュ（取得済みの場合）・変換署名で画像の版を識別する。変更時は旧画像を採用せず、新しい画像を生成する。公開除外・削除・オプション無効化後に古い処理が完了しても画像を復活させない。完成済みの先行画像は閲覧時の文書成果物へ再利用する。


## ファイル変換の実行ログ（#6842）

一覧はエラーの先頭行を幅を制限して表示し、操作列の「実行ログを表示」「ログダウンロード」から全文を確認する。既存のログビューアを共通利用し、表示中は3秒ごとに末尾を取得する。背景の一覧・フィルタ・ページ位置は保持する。

事前変換は `build:<jobId>`、バックグラウンド・オンデマンド変換は `preview:<libraryId>:<fileId>` を識別子とし、ライブラリ用データ領域の `library_<id>/logs/conversions/` にUTF-8のログファイルを保存する。事前変換はジョブ単位、公開後変換は文書単位で追記し、試行番号・公開世代・成果物revisionで実行を識別する。再試行と再公開の過去の記録を上書きしない。

実行時のエンジン・プロファイルID・出力形式・確定パラメータ、対象ファイル、展開・パラメータ統合後の実コマンド（引数の境界を保持するargvのJSON）、タイムアウト、作業ディレクトリ、PID、標準出力・標準エラーの統合出力、終了コード・処理時間、例外、再試行・省略・公開版変更による破棄を記録する。秘密値はコマンドをJSON化する前と出力保存時にマスクする。成功時もプロセス出力を保存する。起動前・入力準備中の失敗は得られた情報だけを記録する。ログの保存失敗で文書変換の結果は変更しない。

`GET /api/build/convert-jobs/log?libraryId=<id>&taskKey=<key>` はライブラリの閲覧認可と所属ジョブの存在確認後、最大512KiBの末尾を行境界で返す。表示の先頭省略を明示し、`download=true` は全文をファイルとして配信する。応答は `Cache-Control: no-store` とする。UIにも既存の行数上限を適用する。過去の未記録実行は状態・日時・保存済みエラーを表示し、詳細ログがないことを明示する。現在の設定から過去のコマンドを推測して生成しない。
