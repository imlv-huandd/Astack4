# AI使用量・概算コスト（#6783）

AIプロバイダ設定の各行の「使用量・コスト」から `/settings/ai-usage?connectionId=<id>` を開く。画面上部の「全体の使用量」は削除済み接続を含む全体集計を開く。管理者専用。参照・CSV・料金追加の全APIにもADMIN認可を適用する。

## 計測と保存

Astack4が呼び出した要約、タグ、タグ辞書の整理案、メタ情報、文書ベクトル、検索語の埋め込みを記録する。プロバイダの契約全体の利用量ではない。接続・モデル・用途・ジョブ・ライブラリ・プロジェクトと名称を呼び出し時に保存する。設定・ジョブ削除時のカスケード削除や、現在設定からの過去利用先の推測はしない。APIキー、認証トークン、入力本文、生成本文、例外本文は台帳に保存しない。

`ai_usage_event` はUUIDで呼び出しを識別し、開始時に `STARTED / UNKNOWN` を独立コミットする。応答内のusageは本文解析・終了理由検証より先に取得し、成功・例外を問わず終了時に別トランザクションで更新する。ジョブの失敗・キャンセル・外側トランザクションのロールバックで既存明細を消さない。アプリによる再試行は呼び出しごとに別UUIDを持つ。プロセス停止などで終了処理を完了できなかった明細は `STARTED` のまま残り、画面では「実行中・結果未確認 / 不明」と表示する。

同期呼び出しの計測区間に限定した `AiUsageCapture` をtry-with-resourcesで管理し、ネスト時も復帰する。記録時はライブラリDBルーティングを解除し、REQUIRES_NEWで管理DBに保存してから元のルーティングを復元する。開始記録に失敗した場合はAIを呼び出さない。終了記録の失敗では開始明細を保持し、不明な消費をゼロとして扱わない。

HTTPエラー・タイムアウト・不正JSONなどでusageを取得できない場合は `UNKNOWN`、利用可能な使用量を取得した場合は `MEASURED`。推定トークンの生成は行わない。SDK内部の再送の個別応答、応答を受信できなかった呼び出しの課金、Cohere埋め込みなどusage非提供のAPIについて正確なトークン数は復元できない。請求側との照合は別途必要。

`ai_usage_metadata` は初回起動の日時を保存し、再起動で変更しない。過去ジョブの合算値は複数接続や検索利用に正確に分配できないため遡及移行しない。

## トークンの意味

- 入力はキャッシュの読取・書込を含む総数、出力は推論を含む総数。埋め込み入力は独立列。キャッシュ・推論の内訳を再加算しない。
- OpenAI互換：`prompt_tokens`、`completion_tokens`、それぞれの詳細のcached/reasoningを使用する。
- Gemini / Vertex Gemini：promptはcache込み、candidatesにthoughtsを加えたものを出力総数とする。
- Bedrock Converse：通常inputにcacheRead/cacheWriteを加え、cache内訳を保持する。outputを出力総数とする。Titan埋め込みは `inputTextTokenCount`、Vertex埋め込みはstatisticsの `token_count` を使う。
- 入出力の欠落はnull。取得分の集計と不明件数を分ける。入力・出力の不整合がある場合もMEASUREDにしない。

## 料金履歴と計算

`ai_model_price` は接続ID・実際のモデル名・通貨・適用開始日時・100万トークンあたりの入力/出力/埋め込み/キャッシュ読取/書込単価を保存する。追加のみで更新・削除APIはない。モデル名には実際に呼び出すIDを指定する（Bedrockの推論プロファイル等も同様）。単価は管理者が契約・リージョンに合う値を登録する。

開始時点で適用可能な最新の料金（同じ適用開始日時では登録IDの大きいもの）を選び、明細へ料金ID・通貨を固定する。本日開始の料金は保存時点以降、将来日は日本時間の0時以降から適用する。過去日での追加は拒否する。料金追加後も、それ以前の未算定明細を遡って計算しない。値の空欄は未設定、明示的な0は無料。必要な単価か使用量が欠ける場合、概算額はnull（未算定）とする。

概算額＝（通常入力×入力単価＋出力×出力単価＋埋め込み×埋め込み単価＋キャッシュ読取×読取単価＋キャッシュ書込×書込単価）÷1,000,000。

BigDecimalで計算し、明細は小数12桁、単価は小数8桁で保存する。画面は小数8桁まで表示する。異なる通貨は合算・換算しない。モデルの長文閾値、バッチ、ツール課金、キャッシュ保管料金、固定費、税、無料枠、契約割引、為替は計算対象外。概算額は請求額とは区別する。

## 集計・画面・CSV

期間は日本時間の開始日0時以上・終了日の翌日0時未満。最大366日。今月・先月・直近30日、任意期間と接続・モデル完全一致・用途・プロジェクト・ライブラリで絞り込む。プロジェクト・ライブラリ候補は保存済み明細の名称とIDから取得し、削除後も絞り込める。

通貨別合計、モデル・用途・ライブラリ別内訳、日別のトークンと通貨別コストをDBで集計する。概算額は判明分だけの合計とし、未算定件数・使用量不明件数を併記する。呼び出し明細は日時・UUID降順で最大100件/ページ、画面は50件/ページ。取得中・取得失敗・0件を区別し、取得失敗時に古い条件の集計を表示しない。料金フォームは共通FormModalを使用する。

CSVは適用中の同一条件で、明細全ページを日時・UUID順に出力する。UTF-8 BOM、CRLF、引用符エスケープ、数式文字の無効化を行う。10万件超では条件を絞るエラーを返し、切り捨てない。REPEATABLE_READトランザクションで出力中の追加・更新との不整合を防ぐ。

## API

- `GET /api/ai-usage/summary`：計測開始日時、通貨別合計、日/モデル/用途/ライブラリ別集計。
- `GET /api/ai-usage/events`：明細とページ情報。
- `GET /api/ai-usage/export`：同条件のCSV。上記3APIにはfrom/toが必須。
- `GET /api/ai-usage/connections`：現存・削除済み接続候補。
- `GET /api/ai-usage/options`：記録済みのプロジェクト・ライブラリ候補。
- `GET /api/ai-usage/connections/{id}/prices`：料金履歴。削除済み接続も参照可能。
- `POST /api/ai-usage/connections/{id}/prices`：料金追加。現存する接続のみ。

参照APIは `Cache-Control: no-store`。月額予算・通知・月末予測・自動停止・請求APIとの照合は今回の対象外。

## 導入・復旧

開発構成のddl-auto=updateでは新規エンティティの表が追加される。ddl-auto=validate構成では起動前に[追加DDL](../migrations/6783-ai-usage.sql)を管理DBへ適用する。既存表・既存データの変更はない。計測開始メタデータは起動時に自動作成する。

配備前にサービスを停止して管理DB・ライブラリDB、暗号鍵、ライセンス、現行JAR、systemd設定、変更対象のフロントエンドソースを同じ世代でバックアップする。復旧は前のJAR・設定・ソースへ戻す。追加表は残せるため通常のアプリ復旧でDBを巻き戻さない。利用履歴を保持し、再起動時に計測開始日時を変更しない。DB復元が必要な場合は停止状態で整合バックアップと対応する鍵を戻す。

料金・利用明細は管理DBバックアップの対象。現時点では保持期限による自動削除は行わない。利用増加に応じてDBサイズとバックアップ容量を監視する。
