# 検索の範囲・条件・タグ活用（#6776・#6778）

## 目的と対象

検索を単一／全ライブラリから任意の複数ライブラリへ広げ、条件による絞り込みと文書の該当箇所への到達を提供する。既存の全文＋意味検索、Windows認証・文書ACL、公開状態・公開期間の判定を維持する。[検索・公開閲覧](search-and-viewing.md) と [AI仕様](ai.md) を併せて参照する。

対象は、複数ライブラリ選択、詳細検索・並べ替え、件数付き絞り込み、フレーズ・除外語、ヒットページへの移動、検索条件の保存・共有、およびタグの絞り込み・単独検索・表示・候補と件数・関連文書・表記ゆれ統合。

## 操作と状態

- 全体検索ではアクセス可能な検索対象ライブラリを複数選択できる。プロジェクト単位の選択を提供する。ライブラリ内検索の既存URLは維持する。「このライブラリ」「全ライブラリ」の切替ボタンは削除し、範囲変更はサイドバー（スマートフォンでは絞り込みパネル）へ統一する。
- 詳細条件は検索対象（文書名／本文／両方）、フォルダ、形式、更新期間、フレーズ、除外語、並べ替え。検索条件の変更時は先頭ページへ戻る。
- 本文のキーワードANDとフレーズは従来どおり同じページ内で照合する。除外語は文書全体を対象とし、別ページに該当する場合もその文書を除外する。
- 検索語、範囲、詳細条件、タグ条件をURLに保持し、再読込・戻る・共有で再現する。共有先でも受信者自身の権限で検索する。
- 名前を付けた検索条件は同じブラウザのローカル保存領域に保存する。アカウント間・端末間の同期は行わない。保存時・復元時の失敗を表示する。
- タグ単独検索では検索語を必須にしない。無条件の初回画面表示で検索は開始しない。

### 検索欄の入力方法（#6788）

- 通常入力は半角・全角スペース等の空白で区切り、各語句をフレーズとして検索する。`学校教育 受信` は「学校教育」の語順・隣接と「受信」を同じページ内で照合する。「学校」と「教育」が離れているだけのページは、通常のキーワード一致にしない。AND／ORは既存の「すべての語を含む／いずれかの語を含む」に従う。
- ASCIIの二重引用符で囲むと、空白を含めたフレーズを指定できる。`"学校 教育"` は1つのフレーズとして扱い、あいまい一致をオンにしても語順・隣接の指定を維持する。文字列の完全一致ではなく、既存の日本語解析を用いたフレーズ検索とする。
- 語句の先頭の `-` は文書全体の除外を表す。`学校教育 -受信料` は「受信料」を含む文書を、別ページに含む場合も除外する。`-"受信 契約"` のような除外フレーズも使用でき、詳細条件の除外語と併用できる。語句の途中のハイフン（例：`NHK-BS`）は除外指定にしない。
- 除外指定だけでも検索できる。空の引用符、未閉じの二重引用符、空白で区切らず他の語句に続けた引用符、合計100語句を超える指定はHTTP 400とし、検索欄の入力を保持してエラーを表示する。URLと保存条件には入力した構文をそのまま保持する。
- あいまい一致をオンにした場合、引用符で囲んでいない通常語句だけは単語分割・誤字補正を許容する従来の全文検索へ広げる。意味検索の埋め込みには通常語句を使用し、明示した引用フレーズと除外指定は意味検索候補にも制約として適用する。
- 検索欄に短い入力例を表示し、既存の `InfoTooltip` から空白区切り、引用符、除外、AND／ORの説明を確認できるようにする。常設の長い説明を追加しない。

## 検索範囲の初期値と旧URL（#6795）

- `/search/:libraryId` で範囲指定がなければ、そのライブラリを初期選択する。`/search` は全体が対象。初期選択をURLへ書き足して無条件検索を開始することはしない。
- ライブラリのチェックをすべて外すと全ライブラリを対象とし、プロジェクト指定中ならそのプロジェクト内を対象とする。複数選択・プロジェクト指定・モバイルでの適用／キャンセルを維持する。
- 旧URLの `scope=all`、明示された `libraryIds`／`projectId` は引き続き有効。ライブラリ／プロジェクトの条件をチップや一括解除から解除した場合も、暗黙の初期ライブラリに戻らない。範囲変更時は検索語・タグ・表示件数・追加オプションを保持して先頭ページへ戻る。

## 検索画面の構成（#6778）

- 上部に検索欄、検索方式、詳細条件、検索条件の保存・共有をまとめる。長い条件入力で検索結果を押し下げない。
- PCでは左側を絞り込み、右側を検索結果とする。絞り込みはプロジェクト／ライブラリ、タグ、形式、更新日を扱い、多数の候補は一部を表示して追加表示できるようにする。重複した候補一覧を並べない。
- 適用中の条件を結果の上に表示し、個別解除と一括解除を提供する。並べ替えは結果側に置く。
- フレーズ、除外語、フォルダ、検索対象、タグのAND／OR・除外等は詳細条件から編集する。詳細条件は編集中の値を保持し、「適用」でURLと検索へ反映する。キャンセルと閉じる操作では反映しない。
- スマートフォンでは絞り込みをパネルで開く。編集中の条件は「適用」で確定し、キャンセルで破棄する。狭い画面でも適用・キャンセルに到達できるようにする。
- 検索結果には文書名、抜粋、代表的なタグ、ライブラリ、更新日、該当ページを優先して表示する。多数のタグやパス・スコア等の補足は展開して確認できるようにする。関連文書は展開時に取得する。
- 検索条件のURL形式、ローカル保存領域、検索APIと権限判定は維持する。詳細条件を開閉しても検索結果を破棄しない。

## 拡張子別アイコン（#6793）

検索一覧では 標準テンプレートの `assets/file-icons.svg` と同一のSVG資産を同梱し、標準テンプレートと同じ拡張子・別名対応で表示する。PDFは赤、Wordは青、Excel／CSVは緑、PowerPointはオレンジとする。未対応・拡張子なしは汎用アイコンへフォールバックする。既存の拡張子表示とスマートフォンでのアイコン非表示は維持する。

## 表示件数とページ送り（#6791）

- 一覧上の「表示件数」で10／20／50／100件を選択する。既定は10件。変更すると検索語・タグ・範囲・追加オプションを保持して1ページ目へ戻る。
- 件数は `size` としてURLに保持し、共有・保存・再読み込み・戻る／進むで復元する。未指定・不正・選択肢外の値は画面では10件として扱う。表示件数だけを選んでも検索は開始しない。
- 複数ページの結果では一覧の上下に同じページングを置く。最初／前／次／最後へ移動でき、先頭では最初と前、末尾では次と最後を無効にする。PCでは近くのページ番号も選べる。
- 総ページ数はAPIの返す検索可能範囲を使用し、上限がある場合も範囲外へ移動しない。0件・1ページの場合はページングを表示しない。スマートフォンでも4つの移動操作と現在ページを表示する。

## タグ

- 手動タグとAI生成タグは利用者向けの検索では常に両方を利用する。種類の選択やタグ名への「(AI)」表示は行わない。既存URL・保存済み条件に残る `tagSource` 指定も無視して両方で検索し、画面のURLから取り除く。タグ名そのものと一致タグの強調は保持する。
- 通常の検索語によるタグ照合と、タグ選択による絞り込みを区別する。選択タグは正規化後の完全一致とし、複数タグのAND／ORと除外を提供する。
- 結果にタグと一致タグを表示し、クリックで条件へ追加できる。タグ候補は現在の検索範囲・条件・権限に従う。
- 件数はページ数ではなく文書数。ライブラリが異なる同名文書は別文書として扱う。全体件数を取得できない場合は上限・候補範囲を明示し、完全な集計として提示しない。
- 表記ゆれ統合は元文書のタグを書き換えず、検索時の正規化と別名設定で扱う。業務上異なる語を自動で同一視しない。
- 関連文書は元文書のタグを用いて探す。元文書と候補の双方で公開条件・ACLを確認し、元文書自身を除外する。

### タグ別名の設定

管理画面のサーバー設定で、キー `search.tagAliases`、値を `{"初期セットアップ":"初期設定","セットアップ":"初期設定"}` のようなJSONオブジェクトとして登録し、有効にする。別名と正式タグを同一の絞り込み条件へ展開する。定義は最大500件、各タグ200文字以内とし、多段・循環定義は拒否する。通常検索の同義語辞書とは分け、タグ条件とタグ表示・集計に適用する。登録・編集は既存の管理APIの認可に従う。

## 該当ページ

- ページ番号が判明し、対応ビューアを選択した結果には該当ページへのリンクを提供する。要約だけの一致や、意味検索だけで見つかった文書などページ位置が特定できない結果に番号を推測して付けない。

標準ビューア `pdfjs`／`svg-document` の1.4.0以降で `page` と `find` を受け取り、同一オリジンの親文書ページからも引き継ぐ。コピー禁止時は検索語による強調を無効とする。新規ライブラリの既定は1.4.0、既存の固定バージョンは保持する。旧バージョンの公開コピーで利用するには、対応版の選択と再生成・再公開が必要。旧版または独自ビューアの文書ではページ位置を表示し、動作が確認できない移動リンクを生成しない。

出典付きAI回答は今回の対象外とする。

## 検索の追加オプション（#6786）

- 通常はキーワード一致で検索する。「あいまい一致」「意味検索を含める」は独立したチェックボックスとし、指定がなければ両方オフにする。タグは検索結果を絞り込む条件として維持し、キーワード未入力時のタグ単独検索も提供する。
- 「あいまい一致」をオンにした場合だけ、検索語の誤字など文字の違いを許容する。URL／APIの `fuzzy=true` で指定する。省略時と `false` は補正しない。意味検索の追加は従来の `searchMode=hybrid`、追加しない場合は `keyword`。明示指定のない画面・検索APIの既定は `keyword` に変更する。旧URL・保存条件に明示的な `searchMode=hybrid` があれば引き続き尊重する。
- 追加オプションだけを選んでも無条件検索を開始しない。変更時は先頭ページへ戻り、キーワード・タグ・検索範囲・詳細条件を保持する。共有URL、保存条件、再読み込み、戻る／進むで各オプションを復元する。
- 意味検索が利用できない範囲では意味検索のチェックボックスだけを無効にする。あいまい一致は引き続き利用できる。意味検索の最低類似度基準も維持する。
- 結果の理由は「キーワード一致」「あいまい一致」「タグ一致」「意味検索の候補」を区別する。あいまい一致をオンにしていても、補正なしで一致する文書は「キーワード一致」とする。厳密に一致するページが別にある場合は、そのページと抜粋を優先する。
- 再現例の `q=代々木&tags=NHK&tags=地上デジタル放送&tags=FTTH` は、通常検索で「佐々木」を誤字補正の対象にしない。「あいまい一致」をオンにした場合にのみ候補に含め、その一致理由を明示する。

## 意味検索の候補採用と一致理由（#6785）

- 意味検索の上位候補は順位だけで採用せず、検索語と文書の埋め込みベクトルからコサイン類似度を計算し、最低基準を満たす候補だけを順位統合へ渡す。内部検索エンジンの距離方式（L2／cosinesimil）ごとに尺度が異なる生の点数や、順位統合後のスコアを採用基準にしない。
- 起動設定 `astack.search.semantic-min-cosine-similarity` の既定値は `0.5`。有限の0以上1以下を受け付け、範囲外は起動時に拒否する。類似度を計算できないベクトル（欠損・次元不一致・ゼロ・非有限値）は意味検索候補として採用しない。全文一致した文書は意味検索の最低基準によって除外しない。
- 既定値は実データの正例／負例を確認した初期値であり、関連性の確率や全モデル共通の基準ではない。モデル変更時や検索品質の調整時には、関連文書が残り無関係な文書が除外されることを再確認する。
- 再現例の `extensions=txt&tags=sbc&q=代々木` は低関連候補を除外して0件とする。同じ範囲の「文書を変換するソフトウェア」「document conversion software」では意味検索の候補を維持する。タグだけの検索と全文一致は従来どおり利用できる。
- 結果の一致理由は「キーワード一致」「タグ一致」「意味検索の候補」を区別する。複数の方式で見つかった結果には該当する理由を併記する。タグ一致だけで意味が近いとは判定しない。意味候補がすべて最低基準未満なら意味検索の適用表示を行わない。
- ACL・公開条件・タグ／形式等の絞り込みと固定候補集合からのページ送りを維持する。

## 互換性と検証

既存の `/search`、`/search/:libraryId` と検索APIを保持し、追加条件がないリクエストの結果・権限判定を維持する。条件の検証はサーバー側でも行う。検索条件はキーワード検索・意味検索・件数取得に整合して適用する。

検証は、範囲選択、AND／OR／除外、タグ単独、期間境界、別名、文書単位集計、権限外候補の非表示、検索条件保存とURL復元、ページリンクを含む。実APIとモックでの確認を区別し、PC幅・スマートフォン幅を確認する。

稼働反映は既存構成を確認して差分を反映し、アプリ・設定・DBのバックアップを作成する。既存のライブラリ・コンバーター・ライセンス設定と検索の互換性を反映前後で照合する。復旧時はアプリとフロントエンドを前版へ戻し、不要なDB巻き戻しを行わない。
