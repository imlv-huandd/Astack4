# 原本からの本文抽出・検索・AI

## 処理の分離

HTML公開、閲覧用変換、検索・AI用本文抽出を独立させる。事前・バックグラウンド・オンデマンドの全方式で原本から本文を抽出し、変換成功や初回閲覧を条件にしない。従来の変換完了イベントによるPDF索引登録は廃止する。

FULL/DIFFビルドが正常完了してから、独立した「検索インデックス」ジョブを予約する。公開成功文書一覧を対象として固定し、非同期処理時に最新原本を確認して抽出する。公開処理は本文抽出を待たない。TEMPLATEのHTML再生成では新しい索引ジョブを作らない。ビルドをせずに原本だけ更新してオンデマンド閲覧で再変換した場合、ビューアの成果物だけを更新する。一覧と静的HTMLは最後の成功公開時点を保持する。検索インデックスの単独実行では最新原本を抽出し、AIもその本文を利用する。公開物と本文索引・AIの一時的な版の差を許容し、次回の差分ビルドと索引処理で一致させる。失敗・中止ビルドを起点に新規予約しない。

名前・パス・ACL・手動タグ・手動メタ情報の索引を先に登録し、本文準備後に本文チャンクへ置き換える。AIの自動後続処理は本文抽出待ちがなくなってから実行する。手動予約も、本文抽出中および再試行待ちの間はWAITINGを維持し、AI接続の実行枠を消費しない。既存タグを入力とする辞書整理はこの待機の対象外。個別の抽出失敗・非対応形式は公開済みHTMLを失敗扱いに戻さず、本文のない文書はAI側でスキップする。生成された要約等のHTML反映は既存の後続TEMPLATEを利用する。

「公開ファイルだけで配信」でもサーバー上の索引作成・AIは利用可能。公開サイトでの検索APIや本文抽出API呼び出しを必要としない。

## 対象形式と抽出範囲

2026-11-06、[#6812](https://developer.astack.jp/redmine/issues/6812) でApache Tika 4.2.0を標準抽出基盤に変更した。PDF・Office・テキストに加え、HTML、MHTML、メール等は導入済みTikaパーサーによる内容判定で扱う。拡張子だけで対応可否を決めない。

| 対象 | 抽出範囲・原本位置 |
| --- | --- |
| PDF | ページ本文と原本ページ位置。開封可能なPDFのコピー／本文抽出禁止属性を無視して取り込む。開封パスワードが必要な文書は拒否。OCR・注釈・フォームの追加抽出は行わない |
| Word doc/docx/docm | 本文。表示内容のみの場合は既存の隠し文字・スタイル継承解決を補助として使用。コメント・脚注・文末脚注・ヘッダー／フッター・削除履歴・埋め込みは本文へ混ぜない |
| Excel xls/xlsx/xlsm | セルの保存済み値。シート名を位置として保持。数式再計算・マクロ実行・外部リンク取得は行わない |
| PowerPoint ppt/pptx/pptm | スライド本文と原本スライド番号。ノート・コメント・マスターを除外。PPTX/PPTMはスライドを元の順序でTikaへ渡し、関係IDの走査順をページ番号とみなさない |
| テキスト・HTML等 | BOM・形式内の明示情報・Tikaの文字コード推定を使用。ライブラリの `searchConfig.sourceTextCharset` で文字コードを明示できる。HTML/XML/Markdown等の本文はTikaの形式に応じた抽出結果を使用 |

`searchConfig.includeHiddenContent` は非表示のOffice本文を含める設定。未指定・falseは表示内容だけとし、既存ライブラリの公開内容を拡大しない。trueは隠し文字・非表示シート／行／列・非表示スライドも検索・AIの対象にする。社内の原本検索など網羅性を優先する用途で選択できる。コメント・ノート・削除履歴・埋め込みの除外はどちらでも維持する。変更後は通常ビルドで公開して新しい設定世代を確定する。

表示内容だけのWord抽出ではDOCX/DOCMの文書既定・段落／文字スタイル・basedOn継承・直接書式を解決する。未定義・循環・不正値・64段超のスタイル継承、および可視性が確定できない条件付きテーブルスタイルは文書単位の解析失敗とする。これは容量・処理時間の制限ではない。Officeの可視性や位置を補うためPOI・Word XML処理を残すが、汎用形式の本文解析を独自実装へ戻さない。

非表示設定はアクセス制御の代替としない。検索結果・抜粋には従来の公開条件・ACL・原本版照合を適用する。AI入力は登録済み索引の版を基準とし、公開条件・ACLを確認する。原本版の再照合は行わない。開封パスワードが必要な文書・形式解析失敗は変換後PDFへ自動フォールバックせず、原本ごとに失敗理由を記録する。

2026-11-06、[#6817](https://developer.astack.jp/redmine/issues/6817) のユーザー指示により、PDFの本文抽出権限はTikaの `AccessCheckMode.DONT_CHECK` で無視する。所有者パスワードによるコピー／抽出禁止と、閲覧に必要な開封パスワードを区別し、空のパスワードで開けないPDFは従来どおり `ENCRYPTED_DOCUMENT` とする。原本PDFの暗号化・権限属性は変更しない。抽出器署名を `tika-4.2-source-v2` へ更新し、旧ポリシーの処理結果と区別する。旧ジョブの `EXTRACTION_FORBIDDEN` 履歴は保持し、新しい索引ジョブで取り込み直す。

## チャンクとページ

本文は最大12000文字のチャンクへ分ける。`chunk_number` は原本内の順序、`source_location` は原本上の場所。Officeのシート・スライドを変換後ページとみなさず `page_number` はnullとする。原本PDFのページジャンプは、原本PDFをそのまま出力PDFとして使用し、索引版と公開版が一致する場合だけ設定する。他の出力形式では原本ページ位置だけを保持し、変換後ページへの誤ったジャンプを生成しない。

AIはチャンク順＋IDで安定した取得を行い、ページ番号のない本文も処理する。ページ粒度ベクトルの文書IDもチャンクIDを利用でき、位置がない場合はページ番号を保存しない。

## 永続状態・再利用・安全性

管理DBの `search_index_job` に起点ビルド、ライブラリ、状態、日時、設定の指紋を、`search_index_job_file` にジョブごとの文書・実際に抽出した原本snapshot・版・結果を保存する。公開時のsnapshotは別に保持し、対象確認とビューアの版照合に使用する。`source_text_task` は現在の抽出状態と再利用可能な結果の指紋を管理し、対応する索引ジョブIDを持つ。OpenSearch文書の`file.indexed_source_revision`にも同じ版IDを保存し、検索側の日付の秒精度に依存せずAI入力を照合する。文書状態はPENDING／PROCESSING／READY／FAILED／UNSUPPORTED／EXCLUDED。本文自体・認証情報はタスク履歴へ保存しない。

同じ原本版・原本接続・抽出器署名の成功結果は再利用し、設定変更による再変換だけでは抽出し直さない。新しい原本版や抽出方式ではAI要約を無効化する。削除・公開対象外になったタスクの索引と要約を削除する。

キャッシュ再利用前にも現在の原本を確認する。更新確認はライブラリのMETADATA／CHANGED_HASH／ALWAYS_HASHに従う。METADATAはサイズ・更新日時、CHANGED_HASHはメタ情報変更時のハッシュ、ALWAYS_HASHは毎回のハッシュで比較する。メタ情報方式では追加ハッシュ計算を行わない。同サイズ・同日時を維持した変更の検出限界は選択した更新確認方式に従う。原本取得前後のサイズ・更新日時と固定コピーのサイズを確認し、読み取り途中の更新は最大3回まで再試行する。公開時から原本が更新されたこと自体を失敗理由にしない。

索引確定前後に、公開成功文書との原本接続・パス一致と公開条件を再確認する。公開されていない新規文書や読み取り途中で変更された原本を本文索引へ採用しない。索引が先行してもクロール用の`build_file`情報を更新せず、次の差分ビルドによる原本更新検出を維持する。AIは最新の索引ジョブと抽出原本版を照合し、古い索引・AI結果による上書きを防ぐ。認可・公開条件の最終判断は既存の検索・文書アクセス制御も引き続き適用する。

起動時に実行中のジョブを待機へ、PROCESSING文書をPENDINGへ戻して復旧する。ジョブ内の抽出失敗は最大3回試行し、最終結果を文書別に記録する。READYの同じ原本版は再利用する。UNSUPPORTEDは同じ版で自動再試行しない。明示的な再実行は新しいジョブに記録し、成功文書は再利用して失敗文書を処理する。原本更新または抽出器署名更新で新たな処理対象になる。旧版から残ったジョブ未所属のFAILEDタスクは、従来どおり5分間隔・最大3回の再試行を継続する。

## 容量・時間と安定運用

ユーザー指示により、原本サイズ64MiB・本文200万文字・PDF10000ページ・抽出60秒の固定上限は撤廃する。Tikaの文字数上限は無制限、解析全体・無進捗の期限も無制限に設定する。ストレージ接続・API通信の既存タイムアウト、XMLの外部参照禁止や構造・圧縮率に対する保護は維持する。

一文書につきSpringを起動しない別のJavaプロセスを起動する。解析結果は一時ディレクトリのJSON Linesへ12000文字以下のチャンクで書き出し、正常終了を確認してから本体が順に読み取り、128チャンクずつ索引登録する。本体へ本文全体を一括ロードしない。一時ファイルは成功・失敗・取消で解放し、解析プロセスの終了時には子プロセスも破棄する。

固定の文書容量・時間制限をなくしても、利用可能なディスク・メモリは有限である。解析JVMのヒープは既定512MiB（本体JVMの `astack.sourceText.workerHeap` システムプロパティで変更可能）。解析時のメモリ不足・異常終了を検出したらその文書を失敗とし、本体・他の文書の処理を継続する。同時抽出は既存の直列キューで制御する。期限なしで進行しない文書はジョブ一覧の停止操作で終了でき、停止後に再実行できる。

失敗理由は `ENCRYPTED_DOCUMENT`、`EXTRACTION_FORBIDDEN`、`CHARACTER_ENCODING_ERROR`、`DOCUMENT_PARSE_FAILED`、`PARSER_DEPENDENCY_MISSING`、`PARSER_PROCESS_FAILED`、`UNSUPPORTED_FORMAT`、`SOURCE_CHANGED`、`EXTRACTION_FAILED` で区別する。暗号化・抽出禁止・文字コード・文書構造・依存クラス不足は自動再試行しない。解析プロセス異常やストレージ等の一時障害は既存の最大3回の再試行を使う。Tikaが部分解析を例外メタデータへ記録した場合も成功本文として採用しない。本文の索引登録が途中で失敗した場合はその文書の本文を除去し、公開条件を再確認してファイル名等のメタ情報を残す。

待機・実行中のジョブは権限を持つ管理利用者が `POST /api/index-jobs/{id}/cancel` で停止する。永続状態をCANCELLEDにし、抽出側の監視が解析プロセスを終了する。停止したジョブのAI後続処理は作らない。成功済み文書の処理結果は保持する。サービス停止による中断はWAITINGへ戻して再起動後に再開し、未処理状態が残るジョブをSUCCESSにしない。

抽出器署名と非表示・文字コードの設定指紋を保存し、旧方式や異なる設定の結果を再利用しない。反映時に無断で全ライブラリを再索引化せず、次のインデックス作成・通常公開で新しい抽出方式を適用する。再起動ではPROCESSINGをPENDINGへ戻して再開する。

エラー記録へ本文・認証情報・原本パスを出力しない。依存クラス不足は例外型と不足クラス名だけを記録し、管理画面は安全な理由コードを表示する。公開HTMLの復旧は既存の公開世代バックアップに従い、索引の再構築は成功公開世代を対象に予約する。

配布物は `python3 scripts/verification/verify-source-text-worker.py <backend.jar>` でネスト依存JARが非圧縮格納であることと、実際のSpring Bootローダー経由のPPT本文抽出を検証する。旧配布物ではpoi-scratchpadが外側JAR内で圧縮されており、ファイルが含まれていてもHSLFSlideShowをロードできずNoClassDefFoundErrorとなった。通常の単体テストだけでなく、配布物そのものの検証をCIと反映前確認へ含める。

## ジョブの処理ログ

検索インデックス詳細はファイル別結果表に代えて、他のジョブと共通のログ表示・保存操作を提供する。ファイル別のDB記録は進捗・再実行・復旧のため保持し、既存の詳細APIも維持する。ジョブごとに `data/libraries/library_{libraryId}/logs/index_job_{jobId}.log` を保存する。表示は末尾512KiBを3秒間隔で取得し、完了時も最終出力を取得する。ダウンロードは全文を配信する。導入前のジョブは詳細な処理経過を復元せず、未保存と明示する。

`searchConfig.indexLogLevel` は1=ERROR、2=WARN、3=INFO、4=DEBUG、5=TRACE。未指定はビルド設定を継承し、そちらも未指定ならINFO。予約時の有効値をジョブに固定し、変更は次のジョブから反映する。ログレベルだけの変更では再ビルド要求・索引世代・抽出キャッシュを無効にしない。

ERRORは文書・ジョブの失敗、WARNは再試行・対象外・抽出警告、INFOは予約・開始/再開・進捗・サービス停止、DEBUGは文書IDごとの結果・再利用・処理時間、TRACEは索引登録のチャンク数を記録する。終了状態と成功・失敗・対象外の集計はログレベルによらずRESULTとして保存する。本文・認証情報・原本パス・例外メッセージは出力しない。ログ書き込みのI/O失敗はサーバーログへ安全な警告を記録し、索引処理自体を失敗させない。
